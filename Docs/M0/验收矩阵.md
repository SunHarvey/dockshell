# M0 与 MVP 验收矩阵

日期：2026-10-18。M0 不创建产品 UI，不选择正式 SSH 后端，不 fork 或修改第三方源码。

## 1. 证据等级

- **本机实测**：在当前 macOS 27.0.1 / arm64 / Swift 6.4 环境执行并记录结果。
- **源码/文档确认**：官方实现或文档存在相应能力，尚未完成指定环境的集成测试。
- **待实测**：需要 macOS 14、测试服务器、故障注入或完整应用才能验收。
- **不支持/需适配**：指定版本未提供对应实现，或需要额外工作；不得标记为通过。

构建目标为 macOS 14.0 只是编译设置，不可代替 macOS 14 运行验证。`ssh -Q` 或库算法列表只证明编译能力，不证明默认启用，也不证明已与旧服务器成功协商。

## 3. 服务器集成与目标系统验收

以下项目不能由当前离线探针替代，未执行前全部保持待实测。

| 检查项 | 通过标准 | 所需条件 |
|---|---|---|
| macOS 14 运行 | 原生 arm64 / x86_64 目标及其所有动态依赖在 macOS 14 正常启动、连接、退出。 | macOS 14 测试机；正式构建依赖。 |
| 密码认证 | 正确密码登录，错误密码有明确提示；密码不进入参数、环境、数据库或日志。 | Linux 测试服务器；凭据安全输入/Keychain 集成。 |
| 私钥认证 | 使用受支持的 RSA/Ed25519 私钥登录；加密私钥可通过口令解锁，错误口令有明确提示。 | 测试密钥与 Linux 服务器。 |
| 本机 ssh-agent | 枚举并使用隔离测试 agent 的密钥；agent 不可用、拒绝签名或无身份时明确失败。 | 测试 agent 与服务器；不复用未知用户身份。 |
| 主机指纹 | 首次确认、取消、再次连接、密钥变化均符合预期；拒绝信任后不发送认证材料。 | 可控主机密钥及应用信任流程。 |
| PTY 与尺寸 | 正确创建 PTY；远端 `stty size`、vim、top、htop 随窗口变化更新。 | Linux 测试服务器；后续终端 UI。 |
| 背压 | 远端持续高速输出、消费者暂停/变慢后字节完整且按序，进程内存保持有界。 | 可控输出源；RSS 与字节计数/校验记录。 |
| 旧 AES-CBC | 对指定服务器明确选择相应 `aes128-cbc` 等算法后成功协商；记录实际协商结果。 | 隔离旧算法服务器。 |
| 旧 group14/SHA-1 | 对 `diffie-hellman-group14-sha1` 记录实际协商和失败原因。 | 隔离旧算法服务器。 |
| 旧 ssh-rsa | 分别测试主机签名及用户认证中的 RSA/SHA-1，并与 RSA/SHA-2 区分。 | 可控服务器算法配置。 |
| 普通断网 | socket 错误或 EOF 后状态明确，可手动重连。 | 可控网络中断。 |
| keepalive 心跳断线检测 | 保持 TCP 表面连接但丢弃数据的黑洞场景中，在配置的探测阈值后判定失联；不能只依赖本机网络路径变化。 | 隔离网络故障注入环境；不修改用户全局网络配置。 |
| 睡眠与唤醒 | 睡眠后唤醒，存活连接恢复可用；失效连接明确提示并能手动重连；旧任务与通道被释放。 | 真实 macOS 睡眠唤醒；可控服务器超时。 |
| 重复重连 | 多次连接、取消和重连后没有旧事件污染、重复输入、文件描述符或线程持续增长。 | 连接生命周期实现及资源观察。 |
| 中文与 IME | 中文文件名、输入、输出、emoji、跨块 UTF-8 正确；组合输入期间不发送未提交文本。 | M3 及后续 UI；系统输入法。 |
| 滚屏设置 | 默认 10000 行；设置可调整；超限只淘汰已滚出的历史，字节解析不丢弃。 | M3 及后续 UI。 |
| 凭据持久化 | 重启后会话仍在，密码/口令从 Keychain 获取，数据库与日志无认证材料。 | M2 及后续应用。 |

旧算法在 M0 中只评价兼容能力，不能把“查询到”当作“已启用”。正式启用策略由选定路线后的安全设计明确，不通过全局放宽配置完成验收。

## 4. 私钥格式验收

格式、密钥算法和加密参数需要分别记录；不能只用“支持私钥”概括。

| 输入 | 最低检查范围 | 不支持时的行为 |
|---|---|---|
| OpenSSH | RSA / Ed25519；未加密与加密；bcrypt 参数及加密算法范围。 | 在连接前提示不支持的格式、算法或参数；不得误报为服务器密码错误。 |
| 老式 PEM | 传统 RSA PKCS#1、适用的 EC PEM；区分未加密与加密，以及 PKCS#8。 | 明确指出当前后端不支持该具体格式，给出重新选择或手动导出受支持格式的说明。 |
| PuTTY `.ppk` | 识别 `PuTTY-User-Key-File-2/3` 等头部；逐后端核实。 | 若不支持，明确提示需使用 PuTTYgen 等工具手动导出 OpenSSH 格式；MVP 不自动安装转换工具。 |
| 格式损坏/文件不可读 | 截断文件、错误头部、权限变化、文件移动。 | 本地化报错；保留可重新选择文件的路径，不记录文件内容或口令。 |

私钥管理已选择引用外部文件。对格式的识别不能打印私钥正文，测试也不应自动读取用户 `~/.ssh` 中的密钥。

## 5. M0 决策规则

M0 交付代码、可重复的本机验证结果、能力对比与推荐。不能执行的目标系统或服务器场景保留为待实测，不伪造通过记录。

用户根据报告选择路线后，才允许进入 M1。若选择方案仍需要第三方 fork、补丁或新的密码学构建依赖，必须在实施前列出具体版本、来源、改动和维护成本并获批准。
