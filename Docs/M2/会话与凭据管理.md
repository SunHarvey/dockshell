# M2：会话与凭据管理

历史里程碑记录；当前终端与设置及依赖以 [M3 文档](../M3/离线终端与设置.md) 为准。

日期：2026-10-27。实现范围为会话与分组 CRUD、搜索、SQLite 持久化、私钥文件引用，以及 Keychain 密码/口令管理。继续使用当前目录、Swift 6、macOS 14、CLT 和系统依赖。

## 行为

- 工具栏“新建会话”或 ⌘N 打开表单；选择名称、主机、端口、用户名、认证方式及分组。
- 支持密码、外部私钥文件和本机 ssh-agent 三种配置。真实认证、主机信任和终端连接按 M4/M5 实现。
- 密码或私钥口令只进入 Keychain；SQLite 只保存 UUID 引用。
- 编辑时不读取、不回填现有秘密；留空保留原凭据，取消保存则移除；填入新内容使用新的 Keychain 项。
- 私钥保留在用户选择的位置，数据库只保存书签。不可读、过期或已移除的文件明确报错；PPK 提示导出为 OpenSSH。M2 不声明密钥解密或 SSH 登录已经通过。
- 单层分组支持新建、重命名、删除；删除分组将会话移到“未分组”。
- 搜索名称、主机、用户名和分组名称，可叠加分组过滤。
- 删除会话需要确认；同时清理其保存的凭据。

## 存储

通过系统 Application Support API 创建 `DockShell/sessions.sqlite`。不写死用户目录，不使用 Homebrew 运行库。新目录权限 0700，数据库文件与实例锁文件 0600。

SQLite 仓库由 Actor 隔离：使用预编译参数绑定、外键、WAL、FULL 同步和事务。`PRAGMA user_version` 管理 schema；当前为版本 1。高于当前版本或损坏的数据文件会报错并保留，不自动覆盖。

数据库包含：

- `session_groups`：分组 UUID、名称和唯一规范化名称。
- `sessions`：非敏感配置、认证类型、外部私钥书签、凭据 UUID 和分组 UUID。
- `credential_cleanup`：待清理 Keychain 项的 UUID。

Keychain 使用 `dev.dockshell.credentials` service 和 UUID account；不以主机、用户名或秘密作为日志/账号字段。Security 调用在独立 Actor 内执行。访问被拒绝、锁定或需交互时提供本地化错误，不扩大访问权限。

## 跨存储失败处理

SQLite 与 Keychain 不能组成一个原子事务，因此使用持久清理记录：

1. 为新凭据生成 UUID，并先提交清理记录。
2. 将秘密写入新 Keychain 项。
3. 在 SQLite 事务内保存会话、保护新引用、将旧引用加入清理记录。
4. 删除不再引用的 Keychain 项；成功后移除清理记录。

阶段 2/3 失败时原会话和原凭据保持可用；新项可按已提交记录回收。阶段 4 失败时会话更改已经保存，界面显示清理警告，并提供重试，下次启动也继续清理。记录中不包含秘密。

业务 Actor 使用显式操作门闩，避免跨 await 重入导致两个更新相互清理。仓库持有生命周期进程锁，防止另一个实例在新凭据提交前执行恢复清理；第二实例会得到明确提示。

## 运行与验证

先用 ⌘Q 退出旧版本，再在当前项目目录执行：

```sh
sh Scripts/run.sh zh-Hans
sh Scripts/test.sh
```

在正常桌面会话验证真实 Keychain（只创建并删除随机 service 下的合成测试项，不读取已有用户项）：

```sh
DOCKSHELL_KEYCHAIN_TEST=1 sh Scripts/test.sh
```

需要图形桌面的视图构造检查：

```sh
DOCKSHELL_UI_SMOKE=1 sh Scripts/test.sh
```

Release：

```sh
sh Scripts/test.sh release
```

自动检查使用随机临时数据库和合成凭据，覆盖会话/分组、中文及 emoji、搜索过滤、数据库重开、密钥文件书签、参数校验、文件权限、DB/WAL 不含秘密、Keychain 和数据库故障注入、崩溃恢复、并发更新、损坏数据库与高版本保护。实际 Keychain 检查需显式设置上述开关。

人工验收：

1. 新建一个分组和密码会话，保存后选中可看到配置摘要。
2. 编辑名称但不填写密码，保存后原凭据引用保留。
3. ⌘Q 退出并重新启动，会话和分组仍在。
4. 改为私钥并选择自己的文件，按需保存口令；移除文件后编辑保存应提示重新选择。
5. 新建 agent 会话，切换分组并搜索名称、主机和用户名。
6. 重命名分组；删除分组后会话仍在未分组；确认删除会话后列表刷新。
7. 通过失败注入验证凭据清理警告与恢复，不需要锁定或破坏个人钥匙串。

本地 ad-hoc 签名在代码更新后可能触发 Keychain 的身份访问限制。应用会报告拒绝/需授权；不会将 ACL 改为所有程序可访问。稳定 Developer ID 身份与分发配置仍在 M6。

## CLT 兼容

当前 SDK 的 `@State` 名称会优先选择新版 SwiftUI 宏，而 CLT 缺少其插件。本轮通过 `ViewState<Value>` 类型别名明确使用系统现有的 `SwiftUI.State<Value>` 属性包装器；这不是第三方补丁。具体构建与运行结果记录于本文件后续实测节。
