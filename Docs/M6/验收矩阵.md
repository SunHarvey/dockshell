## 真实 Keychain 与新进程验证

`M6KeychainRestartVerification` 只使用新生成的合成秘密和隔离夹具，不读取个人密码、个人私钥、应用正式凭据或用户已有主机记录：

1. 父进程创建仅当前用户可访问的临时目录、随机 Keychain service、真实 SQLite 仓库，以及一次性的 loopback sshd。
2. 通过正式 `WorkspaceService.save` 保存密码会话与加密外部私钥会话；SQLite 中只有不透明凭据 UUID 和外部私钥书签。
3. 关闭父进程 SQLite，启动同一验证器的新进程。子进程重新通过 `WorkspaceService.load` 打开数据库，从会话配置取得凭据引用，再读取真实 Keychain。
4. 合成密码与内存中预期摘要匹配；加密私钥口令通过正式 `OpenSSHTransport`、签名 helper 和 askpass 路径完成真实 loopback SSH 登录。任何密码、口令或主机确认交互都会使检查失败。
5. 子进程只向父进程返回固定成功标记或有限 Keychain 错误标签。父进程删除本轮随机 Keychain 项，并再次确认它们已经消失，最后清理进程与临时文件。

秘密不出现在参数、环境变量、数据库、清单、known_hosts、sshd 配置或日志中。一次性清单只包含引用、公开主机公钥和合成密码摘要；随机 nonce 用于将子进程限制在父进程的本轮夹具。子进程仅接受系统私有临时目录下、当前用户拥有且权限为 0700 的特定目录，以及严格前缀的随机测试 service。它不是一个可指定任意 service / account 的 Keychain 读取入口。

这个检查证明“真实 SQLite 保存 → 新进程加载 → 真实 Keychain 取用 → 加密私钥 SSH 认证”的完整链路，并验证密码的持久化回读。它不会把本地公钥认证伪装成真实 Linux 密码认证；真实 VM 的密码保存、应用退出和重启登录仍需单独操作。系统 Keychain 如因代码签名身份、ACL 或锁定状态拒绝访问，测试明确失败并保留现有访问限制，不自动扩大 ACL。

在构建成功后**单独运行一次**，避免完整测试脚本中的 UI / 搬迁检查重复触发可选集成：

```sh
export DOCKSHELL_ROOT="$PWD"
. Scripts/common.sh
bin_path=$(swift_build -c debug --show-bin-path)
DOCKSHELL_KEYCHAIN_RESTART_TEST=1 "$bin_path/dockshell-verify" "$PWD/Build/debug/DockShell.app"
```

默认 `sh Scripts/test.sh` 仅运行 restart 入口范围拒绝检查，不因默认回归访问真实 Keychain。该可选集成使用系统 `/usr/sbin/sshd`，不启用系统远程登录、不修改 authorized_keys、用户 agent 或服务器认证策略。夹具保留 `StrictModes=yes`，关闭转发并仅执行固定输出命令；支持时仅对本轮临时 daemon 关闭来源惩罚，正式连接不改变服务器保护。

## 持久化路径安全

本轮审计发现旧 SQLite 打开路径可能跟随已有符号链接，并对路径指向的目标收紧权限。现改为：

- 不改变已有父目录权限；最终数据目录必须是当前用户拥有的真实目录，且不允许 group / other 写入。
- DB、进程锁及已有 `-wal` / `-shm` / `-journal` 文件通过 `O_NOFOLLOW` 打开，再检查实际文件描述符的所有者、普通文件类型与单硬链接。拒绝 FIFO、目录、符号链接和硬链接。
- 仅通过已验证描述符设置 0600，避免对符号链接目标执行路径 chmod。合法旧数据库的 0644 权限可安全收紧。
- `sqlite3_open_v2` 使用 `SQLITE_OPEN_NOFOLLOW`，并在执行 SQL 前核对文件身份；SQLite 最低运行版本显式检查 3.31.0。该标志自 SQLite 3.31.0 引入；macOS 14 上的完整运行仍列为实机验收。[SQLite 3.31.0 发布记录](https://www.sqlite.org/releaselog/3_31_0.html)、[SQLite 打开标志](https://www.sqlite.org/c3ref/c_open_autoproxy.html)

macOS 的系统祖先路径 `/var` 本身是符号链接，SQLite 的 NOFOLLOW 也会检查祖先。先拒绝应用最终数据目录的符号链接，再用 POSIX `realpath` 解析系统祖先并复核目录 inode，可保留安全检查同时支持系统临时目录。没有用 `URL.standardizedFileURL` 做这一转换，因为本机 Foundation 会将 `/private/var` 再标准化回 `/var`；本轮实测曾因此收到 `SQLITE_CANTOPEN_SYMLINK`，现已修复。

防护边界是当前用户控制的数据目录，不声称抵御已能任意执行同用户代码的进程。默认 `M6PersistenceSafetyVerification` 使用自己创建的临时文件验证正常重开、父目录原权限保持，以及 DB / lock / sidecar 的 symlink、hardlink、FIFO 和目录拒绝，检查目标字节与权限均未改变。M2 的损坏 / 未来版本数据保留回归继续适用。

## 私钥格式验收边界

| 格式 | 实际覆盖 | 支持边界 |
|---|---|---|
| OpenSSH | 临时 Ed25519 无口令 / bcrypt 口令；外部 RSA 真实 Linux 登录 | 预检识别单把 Ed25519、RSA、标准 NIST ECDSA。未知 KDF / 算法、多密钥或损坏结构明确拒绝；不承诺 FIDO / SK / DSA |
| 老式 PEM | 隔离本地 sshd 的 RSA 无口令 / 加密登录、错误口令后恢复 | 只承诺已识别 RSA / EC 头与有限传统加密封装；完整解密由系统 SSH 决定 |
| PKCS#8 PEM | 已识别部分未加密与 PBES2 封装的结构检查 | 尚未完成真实认证矩阵，不宣称任意变体均可使用 |
| PuTTY `.ppk` | 扩展名、文件头及改名文件拒绝检查 | 不支持；应用明确提示使用 PuTTYgen 导出 OpenSSH 格式，不静默失败 |

私钥路径仅作为用户所选外部文件引用，数据库不保存私钥内容。网络握手旧算法与私钥容器的静态加密方式是不同维度；没有为本轮验收开启 AES-CBC、SHA-1 RSA 或旧 DH 兼容选项。

## 人工验收步骤

每项记录系统版本、构建标识、日期与结果；不要记录密码、口令、私钥内容或完整终端秘密输出。

1. **密码持久化登录**：在 DockShell 中为授权服务器保存密码到 Keychain，连接并确认成功；主动断开，⌘Q 完全退出，再启动同一签名应用。会话列表应保留，直接连接应成功且不再次询问密码。测试后按需要在会话编辑器移除保存的密码。
2. **真实中文输入法**：切换简体中文输入法，在 shell 和 `vim -u NONE -n` 中连续拼写、选词、取消组合、移动光标再提交。确认组合期间没有提前发送字母，候选位置随光标且提交不重复；再检查中文文件名和 emoji 输出。
3. **全屏程序**：分别运行 vim、top、已安装的 htop，反复缩放窗口；界面布局、鼠标报告、退出后 shell 状态正确。若服务器未安装 htop，记录“未执行”，不要未经授权安装。
4. **真实睡眠唤醒**：在无重要前台任务的连接中手动让 Mac 睡眠。唤醒后应保留显示与连接并提示等待心跳确认，不自动认证；连接失效时应给出原因，点击重连可建立新会话。网络切换后重复，记录实测断线延时。
5. **macOS 14 实机**：运行打包应用，检查会话持久化、Keychain 密码 / 私钥、agent、主机确认、字体主题、中文 IME、大输出、窗口同步和断线重连；分别确认架构与系统 SSH 版本。仅在新系统编译不能勾选此项。
