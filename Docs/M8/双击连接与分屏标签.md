## 使用方式

- 单击侧栏会话只选择；双击会话名称或所在行直接新建 SSH 连接。右键连接、编辑和删除继续针对实际点击的会话。
- 分屏后，每个面板上方显示自己的名称、状态点和 ×。点击局部标签选择该面板，键盘输入交给相应终端。
- 局部标签的 × 只关闭该面板。另一个面板保留原连接和内容，并扩大为单面板。
- 顶层标签的 × 关闭该标签内全部面板；顶层标签仍用组合名称表示整个分屏工作区。
- 只剩一个面板时，局部小标签折叠，连接继续由顶层标签显示，终端取回该区域。
- 右上角连接状态菜单仍提供当前面板的取消、断开、重连和关闭操作。

## 实现要点

侧栏使用 macOS `List` 的原生 `primaryAction` 接收双击，替换与列表选择竞争的行手势。操作通过点击事件提供的会话 ID 查找目标，不用先前选中项替代；空白、分区标题或不存在的项不会触发连接。API 说明见 [Apple 官方文档](https://developer.apple.com/documentation/swiftui/view/contextmenu%28forselectiontype:menu:primaryaction:%29)。

每个终端从创建起拥有固定 AppKit 容器，容纳独立的标签宿主与原来的 SSH 内容宿主。分屏和折叠只改变标签可见性及 frame，不更换 SSH 内容的 root view，不重挂终端或重新认证。局部标签独立观察自己的连接状态、提示及当前面板身份。

顶层与局部标签分别使用 `dockshell.tab`、`dockshell.pane` 辅助功能标识前缀，避免首面板 ID 与顶层标签 ID 相同时命中错误的关闭控件。所有新增标签操作沿用既有本地化文案。

侧栏的真实双击证据来自 CUA 驱动的独立窗口：先单击 A，确认没有连接；再双击 B，工厂计数为 1、目标为 B；最后双击 A，工厂计数为 2、目标为 A，显示 B、A 两个独立标签。窗口运行在独立测试 bundle `dev.dockshell.sidebar-verification` 中，只使用临时仓库及合成连接，没有网络或凭据访问，也未操作用户当前 DockShell。

合成 `NSEvent` 的双击在系统 SwiftUI 最小探针中同样未触发该动作。因此默认回归只明确核对原生单击选择及 `primaryAction` 的 target / selector 接线，不把合成事件检查说成真实双击验收。真正双击的结果以 CUA 专项日志为准。

分屏夹具实际操作局部选择和关闭控件，核对关闭主面板后幸存终端身份、顶层 ID 和连接保留，局部标签折叠及重新分屏后恢复。
