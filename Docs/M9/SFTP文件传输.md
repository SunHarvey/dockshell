# M9.2：SFTP 文件上传与下载

M9.2 在右侧文件面板加入多文件上传、下载、串行队列、进度、取消和同名文件处理。每个标签使用独立的传输连接，目录浏览和终端继续使用各自的连接。本轮支持普通文件，文件夹递归传输留待后续。

按用户要求，本轮不修改应用版本、不创建标签、不发布 Release。公开安装包仍为 v0.1.2；体验本轮功能请运行当前源码或使用包含本轮提交的 CI 构建。没有新增第三方依赖。

## 启动与使用

先用 **⌘Q** 退出旧应用，在项目根目录运行：

```sh
sh Scripts/run.sh zh-Hans
```

英文界面使用 `sh Scripts/run.sh en`。双击已保存会话，点击工具栏文件夹按钮展开远程文件面板。

1. **上传**：先浏览到远程目标目录，点击上传，选择一个或多个本机普通文件。目标目录在打开选择器时确定，随后切换浏览路径不会改变已选任务的目标。
2. **下载**：在远程列表多选普通文件，点击下载，再选择一个本机目录。目录、符号链接和特殊文件不作为传输内容。
3. **同名文件**：选择跳过、另存为，或明确确认替换。另存为只修改本次目标文件名，保留已选目标目录。服务端未宣告受支持的 `posix-rename@openssh.com` v1 时，远程同名文件只能跳过或另存为。
4. **查看任务**：文件面板下方显示传输队列和进度，完成任务显示实际目标路径。新入队的文件依次处理；每个标签的队列容量为 100 条。
5. **取消与继续**：可取消单项或全部任务。取消或失败后，剩余任务暂停，点击继续才会再次处理。清除已结束任务不会移除仍需核对的临时文件或提交结果警示。

传输连接复用会话配置、主机信任和 Keychain 服务，但有自己的认证提示；未保存的密码或私钥口令可能需要再次输入。请只在应用内输入，任务记录不保存认证秘密或文件正文。

收起文件面板保留任务。正常关闭标签时，存在未结束任务会先询问；确认后等待取消和清理。如果仍有临时文件或结果未确认，标签会保留以便查看路径，用户明确选择丢弃记录后才关闭。其他标签的任务、终端和目录浏览不受影响。

## 文件提交与同名处理

上传先在目标目录创建独占的 `.dockshell-upload-UUID.part`，下载先在本机目标目录创建独占的 `.dockshell-download-UUID.part`。文件大小、类型及可用的修改信息在传输前后核对；确认数据操作和句柄关闭后才提交到最终文件名。

上传以成功的 SFTP 写入回包、关闭及改名结果判定完成。下载在本机同步文件数据、关闭句柄后进行同目录改名。新目标默认使用不覆盖的提交方式；替换已有文件需要先取得用户的明确选择。目标在传输期间变化时会重新检查或报告变化，不使用先删除原文件再改名的流程。

上传创建请求使用 `0600`，服务端可按 umask 或策略进一步收紧；最终提交沿用临时文件的权限，不保留原远端文件的权限、所有者、ACL 或修改时间。本机新下载文件也以 `0600` 创建，系统 umask 可进一步收紧；替换本机普通文件时沿用其原 POSIX 权限，不承诺复制 ACL、扩展属性等额外元数据。

普通文件来源会进行实际类型检查。远端路径和名称始终保留原始字节；非 UTF-8 或控制字符名称在界面中转义显示。下载的本机建议名称使用安全的展示形式，过长等无法直接使用的名称改为 `download-UUID`，实际保存位置会在任务结果中显示。

## 取消、失败与记录

每次最多处理四个不超过 32 KiB 的块，内存不会随整文件大小增长。进度按已确认的传输字节更新，界面约每秒合并为 10 次发布，并保留最终结果。

取消首先在批次边界进行协作收尾，并尝试清理本任务创建的临时文件；对端超过 3 秒仍无响应时，关闭本标签自己的传输连接。无法确认清理结果时，任务显示临时路径供检查。

网络在创建文件时中断，可能出现文件已创建但句柄回复未收到的情况；网络在提交改名时中断，可能出现最终文件已提交但结果回复未收到的情况。后者显示为结果未确认，保留目标和临时路径，而不会将它记作已完成或普通取消。已经确认成功的提交，仍按成功结果显示，即使用户同时发出了取消请求。

当前队列和记录仅存在于本次应用运行中，不支持断点续传或退出后的任务恢复。进程崩溃、强制退出及系统中断后，临时文件可能需要手动检查。普通关闭标签的等待清理与记录确认流程不等于进程异常退出后的恢复机制。

并发修改检查使用本机文件身份信息，以及 SFTP v3 提供的大小、权限和秒级修改时间等属性，属于尽力检测；协议没有原子的版本比较替换事务，无法保证发现同秒同大小的远端改写。

## 分层实现

| 类型 / 文件 | 职责 |
|---|---|
| `SFTPTransferRequest` 等领域类型 | 固定本次选择的两个端点、进度、冲突、结果与警示 |
| `SFTPFileTransferEngine` | 分块传输、来源校验、临时文件和最后提交 |
| `SFTPTransferLocalFiles` | 本机文件读写、身份和原子提交的协议边界 |
| `SystemSFTPTransferLocalFiles` | 独立休眠 worker、受限工作队列、目录 FD 与文件系统操作 |
| `SFTPTransfersViewModel` | 独立连接、串行调度、认证和冲突决定、进度合并、取消与记录 |
| `SFTPTransferSelectionControls` / `SFTPTransfersPane` | 本机选择器、下载多选、任务列表、双语提示和冲突表单 |
| `SFTPClient.attributes` | 路径与句柄属性查询；具体后端仍通过协议替换 |

底层方案见 [M9.0 技术验证](SFTP技术验证.md)，目录导航及名称展示规则见 [M9.1 目录浏览](SFTP目录浏览.md)。

当前离屏 SwiftUI 宿主未能可靠读取按钮的辅助功能动作，因此界面专项没有自动点击按钮，也没有操作本机文件选择器。已通过的字段、滚动和布局检查，以及模型中的跳过、另存、替换等决定，应与上述人工待验范围分开理解。

默认回归、具有图形桌面的原生界面检查及隔离的真实 SSH/SFTP 集成：

```sh
sh Scripts/test.sh
DOCKSHELL_UI_SMOKE=1 sh Scripts/test.sh
sh Scripts/test-sftp.sh
```

维护者可在已经组装应用后，设置 `DOCKSHELL_SFTP_TRANSFER_TEST=1`，向匹配构建配置的 `dockshell-verify` 传入应用路径，并附加 `--ui-smoke` 运行本阶段专项。合成对端和界面检查不等于真实服务器验收，最终结果以本表的实际记录为准。

手工验证请使用新建的测试文件和已授权的目标目录：先上传、下载并核对内容，再尝试同名跳过、另存为和确认替换，最后测试取消及切换标签。需要测试失败或中断时，保留任务显示的路径，以便核对临时文件和最终目标；不要用私钥、凭据文件或其他个人敏感内容充当传输夹具。
