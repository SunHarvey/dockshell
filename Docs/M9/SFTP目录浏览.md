# M9.1：SFTP 目录浏览

M9.1 将已经验证的 SFTP v3 底层接入应用，提供终端右侧可收起的只读目录面板。每个标签拥有独立的文件连接与浏览目录；本阶段不包含上传、下载、删除、改名或新建目录等用户操作，这些留给 M9.2。

本轮按用户要求不发布 Release，不修改应用版本、不创建版本标签。公开安装包仍为 v0.1.2；体验本轮功能请从当前源码运行，或使用包含本轮提交的 CI 构建。

## 启动与操作

先用 **⌘Q** 退出此前运行的 DockShell，再在项目根目录执行：

```sh
sh Scripts/run.sh zh-Hans
```

英文界面使用 `sh Scripts/run.sh en`。构建仍可使用 Swift 6 Command Line Tools，不需要完整 Xcode；本轮未增加第三方依赖。

1. 双击已保存的 SSH 会话，打开一个远程标签。
2. 点击工具栏的文件夹按钮，展开当前标签的 SFTP 面板。首次打开才建立该标签的文件连接。
3. 双击目录进入；使用上级、主目录和刷新按钮导航，也可在路径栏输入路径后按 Enter。相对路径按当前成功浏览的目录解析。
4. 用名称搜索框过滤当前列表，通过眼睛菜单显示或隐藏以 `.` 开头的项目。列表按目录优先、名称自然顺序排列。
5. 拖动终端与文件面板之间的分隔线调整宽度。面板较窄时展示名称与大小；宽度达到 480pt 时增加修改时间列，窄面板仍可悬停名称查看类型、大小和修改时间。
6. 点击面板的 **×** 或再次点击工具栏按钮隐藏面板。重新展开保留当前目录和文件连接；关闭标签才会同时结束该标签的终端与文件连接。

普通文件目前只展示信息。符号链接和未提供类型的项目也可以双击尝试进入；目标不是目录、没有权限或服务端无法访问时，面板显示明确错误。目录中缺失的属性显示为未知值，不伪造大小或时间。

初始目录来自 SFTP 服务端对 `.` 的解析。文件连接有自己的当前浏览路径，终端中执行 `cd` 不会自动改变它。分屏仍只排列已有终端；右侧文件面板跟随当前选中的标签，每个标签保留自己的目录、过滤条件与显示状态。

## 认证、失败与恢复

文件连接复用原有会话配置、主机信任记录与 Keychain 服务，单独持有 SSH 进程和认证提示。第一次连接或主机密钥变化仍遵守原有指纹规则。未保存的密码、加密私钥口令可能在文件面板中再次请求；不从终端连接提取临时密码，也不将临时输入自动保存。

连接期间可用取消按钮结束本次文件连接；面板顶栏提供手动重连。隐藏面板保留文件连接及其待处理的认证决定，重新展开可以继续；关闭标签会取消认证决定并清理连接。

权限不足、目录不存在及列表超过限制等操作失败会显示中文或英文提示，并保留上次成功的路径和列表。错误条中的刷新针对当前成功目录，不会悄悄把失败目标当成空目录。连接或协议失败时保留浏览上下文供核对，用户可以手动重连；重连会尝试恢复上次目录。

当前协议接口没有独立的闲置连接状态事件，面板不会通过轮询文件列表保持状态。系统 SSH 的心跳仍然运行；闲置期间断线后，面板在下一次文件操作失败时呈现错误。此行为不能记作文件面板已经实现即时断线事件通知。

## 路径与界面边界

- 路径和名称始终保留原始字节，双击导航不从展示文字重建路径，因此可以进入名称不是合法 UTF-8 的目录。
- 中文和 emoji 正常显示，包括使用 ZWJ 的组合 emoji；控制字符、换行、双向文字控制符和无效 UTF-8 字节以转义形式显示。反斜杠也被转义，避免与转义显示混淆。
- 路径栏未编辑时按 Enter 不会将转义文字重新解释为远端路径。手工输入被视为普通 UTF-8 路径；包含非 UTF-8 字节的目录应通过列表导航。
- 快速连续导航只保留最新的待执行意图，按顺序完成已经发出的 RPC；过时结果不会覆盖新目录，连接也不会因一般导航而被取消。
- 目录数量上限为 10000，保留名称和元数据的字节预算为 4 MiB，沿用 M9.0 的包、请求和管道限制。超过边界会报错，不显示不完整列表冒充成功。
- SwiftUI 负责文件表格与提示，原生分隔视图保留同一个终端宿主。展开、隐藏、调整宽度和切换文件面板只改变终端可用尺寸，不重新创建终端连接或清空终端模式。

## 主要实现

| 文件 / 类型 | 职责 |
|---|---|
| `SFTPBrowserViewModel` | 后端无关的连接、目录加载、导航排队、错误与生命周期；只依赖 `SFTPClientFactory` / `SFTPClient` 协议 |
| `SFTPBrowserEntry` / `SFTPBrowserText` | 原始名称身份、类型判断、安全显示、目录优先排序所需数据 |
| `SFTPBrowserPane` | 路径、过滤、隐藏项、表格、属性、独立认证与本地化错误提示 |
| `TerminalTabSession` / `TerminalTabsViewModel` | 每标签文件模型的所有权、懒连接、显示状态和关闭清理 |
| `NativeFileWorkspaceSplit` | 可拖动分隔线及持久的原生终端宿主 |
| `AppContainer` | 选择系统 OpenSSH 实现，分别为终端与文件连接组装认证提示 |

底层方案及认证安全边界继续见 [M9.0 技术验证](SFTP技术验证.md)。所有新增界面固定文案来自简体中文 / 英文 String Catalog。

运行默认检查：

```sh
sh Scripts/test.sh
```

在具有图形桌面的会话中检查原生 UI：

```sh
DOCKSHELL_UI_SMOKE=1 sh Scripts/test.sh
```

维护者需要只运行 M9.1 检查时，可在已经组装应用后设置 `DOCKSHELL_SFTP_BROWSER_TEST=1`，向匹配构建配置的 `dockshell-verify` 传入应用路径，并附加 `--ui-smoke`。该专用模式使用合成连接，不代表已经登录个人服务器。真实隔离 SSH/SFTP 的专项入口仍为 `sh Scripts/test-sftp.sh`。

手工验收建议使用已授权测试服务器：进入目录、回到上级和主目录，测试搜索与隐藏项，检查中文名称和时间信息，再切换两个标签确认各自目录不变。拖动分隔线并运行终端中的全屏程序，确认布局随尺寸变化且内容保留。最后分别隐藏面板、重开、重连、关闭单个标签，核对其他终端和文件面板继续工作。未保存密码的会话应在文件面板单独要求输入；请仅在应用内输入，不把密码加入命令、日志或聊天。
