## 1. Xcode 安装版本要求

- Swift 6 语言能力的基础下限是 **Xcode 16**；这不是当前全部候选依赖图的已验证最低版本。
- 本轮 Citadel 解析图中的 `swift-collections 1.7.3` 声明 `swift-tools-version: 6.4`，因此该锁定图实际要求 **Swift 6.4 工具链**；不能直接在 Xcode 16 下复现。若以后要降低工具链要求，需要另行验证并固定兼容的传递依赖，不在本轮偷偷修改依赖源码。
- Xcode 自身能运行的 macOS 版本与应用最低部署版本不同；应用仍以 **macOS 14.0** 为最低目标。
- Apple 的兼容表显示：Xcode 16 / 16.1 / 16.2 支持在 macOS 14.5 起的指定系统范围内运行。不能因此认为任意新版 macOS 都适合安装旧 Xcode。
- 当前机器为 **macOS 27.0.1**。Xcode 27.1 正式版是对应的工具链候选，但当前未核实到符合免 Apple ID 登录要求的官方下载途径，不能再将登录下载作为建议动作。
- 若另一台开发机仍为 macOS 14.5，Apple 的表中 Xcode 16.2 可运行，但其 Swift 6.0 不满足上述当前 Citadel 锁定图。可将新机器构建的 macOS 14 目标产物放到旧机器运行验证；开发主机系统版本不等于应用最低系统版本。
- 用新版 SDK 编译并设置部署目标 14.0，不等于已经在 macOS 14 上实测。M0 报告需单独列出 macOS 14 运行验收状态。

官方来源：

- [Apple：Xcode SDK 与系统要求](https://developer.apple.com/xcode/system-requirements)
- [Apple：Xcode 下载入口](https://developer.apple.com/xcode/)
- [swift-collections 1.7.3：工具链声明](https://github.com/apple/swift-collections/blob/1.7.3/Package.swift)

## 2. 安装方式

### 2.1 不登录 Mac App Store 的官方方式

以下保留为历史参考，**不满足用户已经明确的“完全不登录 Apple ID”条件**。

使用浏览器打开 [Apple Developer：Xcode 下载列表](https://developer.apple.com/download/all/?q=Xcode)，登录 Apple Account，搜索适合本机系统的正式版 Xcode，下载官方 `.xip`。

这不需要在 Mac App Store 应用中登录，也不要求购买 Apple Developer Program 会员；开发者网页仍需要 Apple Account，不能将其描述成完全不需要账号。[Apple 官方账户说明](https://developer.apple.com/xcode/resources/)

本机 macOS 27.0.1 可按 Apple 兼容表选择 Xcode 27.1 正式版，其自带 Swift 6.4。下载列表中以正式版和实际文件名为准，不编造固定 CDN 直链。

操作步骤：

1. 在浏览器完成官网下载，保存 `.xip` 文件。
2. 在 Finder 双击 `.xip` 解压，得到完整的 `Xcode.app`。
3. 将 `Xcode.app` 移到 `/Applications`。下载压缩包本身不代表已安装。
4. 打开 Xcode，按提示完成许可和必要组件安装。
5. 先执行下列路径检查；只有目录确实存在，才执行后续切换命令。

```bash
ls -ld /Applications/Xcode.app/Contents/Developer
```

### 2.2 已安装完整 Xcode 后的验证

以下命令由用户在本机终端执行；本轮不自动安装 Xcode，不自动执行管理员操作。

```bash
sudo xcode-select --switch /Applications/Xcode.app/Contents/Developer
sudo xcodebuild -runFirstLaunch
xcodebuild -version
xcrun swift --version
xcrun --sdk macosx --show-sdk-version
xcode-select -p
```

预期：

- `xcodebuild -version` 显示所安装完整 Xcode 的版本。
- `xcrun swift --version` 显示 Swift 6.x。
- SDK 查询成功。
- `xcode-select -p` 显示 `/Applications/Xcode.app/Contents/Developer`。

若安装目录或应用名称不同，相应调整 `--switch` 的路径。

## 4. 将 DeckShell 重命名为 DockShell

目标路径：

```text
/Users/harvey/Documents/github-code/DockShell
```

当前会话仍打开 `DeckShell`。为保证本轮写入可访问，先在当前目录完成 M0 文件，用户重命名后这些文件一并保留。不会创建第二份项目副本。

操作步骤：

1. 等本轮文件写入结束。
2. 关闭使用旧目录的编辑器、终端构建和项目窗口。
3. 在另一个终端中执行以下命令。

```bash
if [ -e "/Users/harvey/Documents/github-code/DockShell" ] || [ -L "/Users/harvey/Documents/github-code/DockShell" ]; then
    echo "目标已存在，停止重命名，请先检查内容。"
else
    mv -n "/Users/harvey/Documents/github-code/DeckShell" "/Users/harvey/Documents/github-code/DockShell"
fi
ls -ld /Users/harvey/Documents/github-code/DockShell
```

先检查目标文件、目录或悬空符号链接是否存在；存在时停止，不合并、覆盖或嵌套移动。不能只依靠 `mv -n`：如果目标已经是目录，它仍可能把旧目录移入目标之下。重命名成功后，`ls` 应显示新目录。

4. 在编辑器中重新打开 `/Users/harvey/Documents/github-code/DockShell`。
5. 清理受旧绝对路径影响的临时构建结果后重新构建。源码与脚本应通过相对路径定位项目资源。

如果图形编辑器仍关联旧目录，重新选择新目录即可；不要通过复制文件保留两个同时修改的项目。

## 5. M0 的权限与范围

- M0 只编写无 UI 的最小验证代码及技术报告。
- 正式 SSH 后端尚未确定。
- 原版依赖可用于隔离验证；不创建个人 fork，不修改或打补丁到第三方源码。
- 私钥管理已确定为用户选文件、口令存 Keychain；M0 不自动读取用户现有私钥或密码。
- 没有指定测试服务器时，只执行离线能力、编译和本地进程验证，远端认证与网络故障场景明确标为待实测。
- macOS 14、服务器兼容矩阵和睡眠唤醒必须补充对应环境实测，不能从当前 macOS 27 结果直接推定。
