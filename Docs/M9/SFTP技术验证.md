# M9.0：SFTP 技术验证

本阶段落实已确认的 SFTP 底层路线，不增加文件面板 UI。后续 M9.1 负责目录面板，M9.2 负责面向用户的上传下载任务、进度、取消与冲突交互。2026-10-30 已完成本轮本地回归与授权服务器验收，具体范围见文末；公开 Release 仍为 v0.1.2，本轮没有新增版本标签或安装包。

## 已确认的路线

- 使用系统 `/usr/bin/ssh` 建立独立的 SSH 连接，以无 PTY 管道请求固定的 `sftp` 子系统。
- DockShell 自有代码实现 SFTP v3 二进制编解码，不解析交互式 `sftp` 的文件列表或进度文本。
- SSH 加密、算法协商和登录交给系统 OpenSSH；本轮新增第三方依赖为 0，没有 fork 或第三方补丁。
- 系统 OpenSSH 版本随 macOS 更新，不能通过 `Package.resolved` 固定。最低部署目标继续为 macOS 14，实际版本能力与目标系统运行验收分别记录。

`ssh -T` 禁用 PTY，`ssh -s` 请求子系统，具体参数由应用构造数组，不执行拼接的 shell 命令。远端文件路径只进入 SFTP 数据包。OpenSSH 自身采用 SFTP v3，并通过扩展提供额外能力；v3 文档是已归档的 Internet-Draft，不能称为已发布的 RFC。

依据：[SSH 手册](https://man.openbsd.org/ssh)、[OpenSSH PROTOCOL](https://github.com/openssh/openssh-portable/blob/master/PROTOCOL)、[filexfer-02 草案](https://datatracker.ietf.org/doc/html/draft-ietf-secsh-filexfer-02)。

## 模块与生命周期

| 类型 | 职责 |
|---|---|
| `SFTPByteChannel` | 有序的二进制读写和关闭，不包含终端尺寸接口 |
| `SFTPClient` / `SFTPClientFactory` | 后端无关的文件操作、连接能力和独立文件会话工厂 |
| `RemotePath` / `SFTPDirectoryEntry` | 保留路径与名称原始字节及可选属性，支持 UTF-8 之外的名称字节 |
| `PipeProcessChannel` | 直接启动固定系统 SSH；独立 stdin/stdout 与有界 stderr；取消、回收本进程及其子进程 |
| `OpenSSHSessionPreparation` | 终端与 SFTP 共享主机信任和认证准备规则 |
| `OpenSSHSFTPClientFactory` | 管理每次独立连接的凭据 broker、认证与 SFTP 初始化 |
| `SFTPV3Client` | v3 握手、扩展协商、请求编号、响应匹配、文件句柄与会话关闭 |

SSH 认证成功和文件协议就绪是两个状态。新连接先收到现有签名 helper 的受校验 READY，再发送 `SSH_FXP_INIT(3)`，只有收到完整、受支持的 `SSH_FXP_VERSION` 后才返回可用客户端。SSH 进程存在、退出码为 0 或 stderr 中出现某段文字，都不能替代这一握手。

文件会话拥有自己的 SSH 进程和 broker。新 broker 绑定应用刚启动的实际 SSH PID 及其身份信息；沿用强制 askpass、一次性秘密交付和受限签名 helper。主机确认发生在读取凭据之前，实际 SSH 连接仍严格核对应用专属 known_hosts。已有终端的 broker 不重置、不重新绑定，连接之间不共享临时密码缓存。

已保存的密码和口令从现有凭据仓库读取；未保存的密码或口令由本次连接交互获取。私钥文件、托管粘贴私钥和 agent 沿用既有策略。密码、口令、私钥内容不进入进程参数、环境变量、SQLite 或诊断日志。

创建中取消、认证失败、协议握手失败，以及所有权移交前的取消，均由启动资源持有者关闭 broker 和进程。客户端拿到所有权后负责 `shutdown()`。M9.0 的请求取消会退役本文件会话，关闭其待处理请求和子进程，避免复用仍有回复在途的编号或句柄；终端连接保持独立。面向用户的任务取消和临时文件收尾属于 M9.2。

## 协议与资源边界

当前实现提供规范路径解析、受限目录读取、文件打开/分块读写/关闭，以及验证需要的目录创建、文件删除和改名。M9.0 不把这些底层方法直接接到用户界面，也不实现整文件读入内存的便利接口。

- 路径保留原始字节，拒绝空路径、NUL 和超过 32 KiB 的路径；子项拼接拒绝路径分隔符。
- 接收端增量处理分片与合并数据，单包上限 1 MiB，不在读取长度前分配该长度的内存。
- 会话最多保留 32 个待响应请求，使用请求编号匹配乱序回复，拒绝未知编号、错误响应类型及损坏结构。
- 每个客户端跟踪自己的句柄，限制打开数量，拒绝跨会话句柄。
- 单次读写默认最多 32 KiB；服务端宣告 `limits@openssh.com` v1 时，进一步按数据及包长度限制收紧。
- 管道输入、输出环形缓冲各 64 KiB，stderr 仅保留 32 KiB 的内存尾部。写入队列和协议发送任务分别限制数量与字节数；目录结果也有数量与保留字节数上限。
- 专用 IO 线程阻塞等待，监督线程睡眠于 `poll`，没有空闲轮询定时器。Swift Actor 负责状态和异步协调，阻塞 IO 不占用主线程。

这些是各层资源限制，不等于整个应用或每条连接的总内存承诺。吞吐、大目录与面向用户传输队列的调优属于后续阶段，需要实际测量。

## 覆盖与完整性规则

普通 v3 `RENAME` 在目标已经存在时应失败。只有服务端宣告受支持版本的 `posix-rename@openssh.com`，客户端才允许请求替换；没有该能力时返回明确的“不支持”，由后续界面提供另存为。客户端不会用先删除目标再改名来模拟安全覆盖。

低层 WRITE 返回成功仅表示收到对应操作的成功响应。传输任务还需要等待所有写入、CLOSE 和最后提交成功；尚未实现的文件面板不能据此宣称用户上传任务已经交付。取消不能撤回已经送达服务端的操作，连接丢失后的提交结果可能不确定。M9.2 将实现临时文件、提交状态与残留提示。

1 MiB 回环校验使用生成的合成字节，包含 NUL 和全部字节值。上传后再通过同一协议读回，检查精确字节数与本地 SHA-256；不依赖服务器安装校验命令，也不把文件正文打印到日志。

## 验证入口

默认回归：

```sh
sh Scripts/test.sh
```

它包含离线系统 SSH 管道检查、固定 SFTP 启动参数检查和合成协议对端检查。合成协议检查覆盖分片、乱序、短读取、版本和扩展、请求上限、损坏回复、取消及资源释放，不代表已登录真实 SSH 服务。

隔离的本地 SSH/SFTP 集成：

```sh
sh Scripts/test-sftp.sh
sh Scripts/test-sftp.sh release
```

该入口使用当前用户启动的回环 sshd、生成的主机/用户测试密钥、临时 known_hosts 和独立 agent，不启用系统“远程登录”，不改个人 authorized_keys、原有 agent 或应用正式凭据。测试只在自己的临时目录操作文件。它覆盖 OpenSSH/PEM、加密口令、agent、二进制往返、特殊名称、独占创建、能力协商和连接取消。无特权公钥夹具不能替代真实密码认证验收。

CI 和 Release 工作流已配置独立的 `test-sftp.sh` 步骤，显式运行本地回环集成，而不是把离线协议测试当成真实 SSH 集成。本轮本地 YAML 与脚本守卫检查通过；远端 Actions 的实际运行结果另行记录。

授权远端验收入口为 `Scripts/test-sftp-remote.sh`，默认不运行。它要求显式设置 `DOCKSHELL_SFTP_REMOTE_TEST=1`、授权主机与用户、认证方式、独立核对的完整 SHA-256 主机公钥指纹；私钥认证另需明确的绝对文件路径。相关配置只包含非秘密端点元数据，密码或口令从输入通道获取。

| 配置 | 用途 |
|---|---|
| `DOCKSHELL_SFTP_REMOTE_HOST` / `PORT` / `USER` | 已授权端点，端口默认 22 |
| `DOCKSHELL_SFTP_REMOTE_FINGERPRINT` | 独立可信渠道核对的完整 `SHA256:...` 指纹 |
| `DOCKSHELL_SFTP_REMOTE_AUTH` | `password` 或 `privateKey` |
| `DOCKSHELL_SFTP_REMOTE_KEY_PATH` | 私钥方式所用的明确绝对路径，不包含私钥正文 |
| `DOCKSHELL_SFTP_REMOTE_SECRET_STDIN=1` | 仅显式自动化输入模式，默认关闭 |

自动化模式本轮由测试控制器在隔离输入终端接收一次凭据，再通过私有匿名 FIFO 交给验证器。密码不进入进程参数、环境变量、普通文件或日志。程序检查 stdin 为 FIFO，并拒绝普通文件、socket 或 TTY；单凭该类型检查不能区分命名与匿名 FIFO，本轮匿名管道的来源由控制器保证。外层输入终端仅用于本轮凭据交付，SFTP 网络数据仍通过无 PTY 管道传输。

手工模式要求 stdin 是当前进程组拥有的前台终端，临时关闭回显并在返回时恢复。该分支调整后已通过编译和静态检查，**尚未重新完成交互验收**；本轮真实密码登录通过的是上述控制器输入模式，不能把这一结果写成人工终端输入已验收。

远端检查仅在本轮成功创建的 `/tmp/dockshell-m9-UUID` 下读写固定测试文件，并清理该目录。若目录创建请求已经发送、结果却无法确认，不删除未确认归属的目录，而是报告可能需要检查的本轮随机路径。遇到非夹具文件也保守保留并报错。本文不记录用户秘密、真实端点或私钥路径。
