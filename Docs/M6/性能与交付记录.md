# M6：性能与交付记录

日期：2026-10-28。产品名 DockShell；当前检出目录为 `/Users/harvey/Documents/github-code/DeckShell`。本记录说明可重复执行的测量方法、原始报告含义与交付范围。下表采用本轮独立 Release 进程的正式测量；较小的开发夹具运行只用于调试验证器，不作为本轮性能结论。

本轮没有增加第三方依赖、个人 fork、上游补丁或第二阶段功能。性能计数器、合成负载和采样任务只存在于独立验证程序，不链接到产品应用，也不收集用户终端内容。

## 测量入口与环境

完整本地性能负载固定为 **64 MiB × 3 轮，随后空闲 10 秒**。使用 Release 构建的 `dockshell-verify`，在独立新进程中仅运行性能模式；不先执行数据库、网络、UI 搬迁或其他完整回归，避免把它们留下的对象与缓存计入本次基线。应用路径参数用于校验随包资源，实际负载由验证进程中的真实终端视图处理。

在项目根目录先完成一次构建，再直接运行已生成的验证程序：

```sh
sh Scripts/build.sh release
export DOCKSHELL_ROOT="$PWD"
. Scripts/common.sh
bin_path=$(swift_build -c release --show-bin-path)
DOCKSHELL_PERFORMANCE_TEST=1 \
DOCKSHELL_PERFORMANCE_REPORT="$PWD/Build/Reports/M6/performance-release.json" \
"$bin_path/dockshell-verify" "$PWD/Build/release/DockShell.app"
```

测量本身不会再次构建。报告路径可省略；省略时只打印结果，不写报告文件。需要诊断不同负载时可以显式设置 `DOCKSHELL_PERFORMANCE_MIB`（2–256）、`DOCKSHELL_PERFORMANCE_ROUNDS`（2–5）、`DOCKSHELL_PERFORMANCE_IDLE_SECONDS`（5–30）；本轮正式结果采用默认值，不能以较小参数的结果替代。性能、真实网络渲染与 Keychain 重启模式必须分别启动进程，不可组合启用。

JSON 中记录系统版本、架构、硬件型号、处理器数量、物理内存、字体、字号、终端行列、滚屏上限和时间。它不包含主机名、用户账号、序列号、服务器地址、密码、私钥或用户终端输出。最低部署目标为 macOS 14，使用更新系统与 SDK 编译和测量不能代替 macOS 14 实机验收。

## 大输出与绘制方法

验证器创建隐藏的原生 `NSWindow`（900 × 560 点）和产品使用的 SwiftTerm CoreGraphics 适配器，字体、字号、主题、历史上限均取产品默认设置，历史为 10000 行。

每轮在 Actor 中生成固定的 128 字节 UTF-8 行，包含 256 色、TrueColor、中文、emoji、重音字符与组合字符，再加 CRLF。生成器按 16 KiB 块输出，经产品的 **64 KiB 有界通道 → 每次至多 4 KiB 的拉取泵 → MainActor 终端输入**。轮首与轮尾另有控制序列和唯一轮次标记，因此实际 `deliveredBytes` 比 64 MiB 正文略大。

生成端与终端 `feed` 入口分别计算完整 SHA-256。两端字节数、摘要以及通道累计写入 / 读取计数必须一致；通道必须排空，高水位不得越过容量，单次 `feed` 不得超过 4096 字节。这样同时检查丢失、重排、改变与无限预读，而不是只核对最后一行是否出现。

每处理约 1 MiB 强制调用真实视图的 CoreGraphics 位图绘制，复用同一张位图，并在输出结束后再绘制一次。隐藏窗口的合成器可能跳过显示帧，所以这里明确测量**包含解析、历史更新与周期性离屏绘制的处理速度**，不把它解释为屏幕帧率。

每轮读取 SwiftTerm 的公开 Unicode 行接口，确认轮尾中文 / emoji 标记正确、轮首已被滚屏淘汰、发生历史裁剪，且总保留行数不超过“10000 行历史 + 当前屏幕行数”。这项检查不修改 SwiftTerm 源码。

## 响应延迟、CPU 与内存

大输出期间，MainActor 上每 20 毫秒安排一次验证专用的休眠唤醒，记录相对预定时间的延迟，并报告观察次数、P95 与最大值。它必须在持续输出期间得到执行机会。该计数描述主线程调度受阻程度，不能替代真实键盘、鼠标和输入法候选操作延迟。

CPU 来自进程 `getrusage` 的用户态与系统态累计时间差，除以对应测量区间墙钟时间。**100% 表示占满一个 CPU 核心**，多核工作可能超过 100%；结果不是整台机器的 CPU 使用率。

内存使用 macOS Mach 进程计数，分别保存物理占用 `phys_footprint` 和驻留集 RSS。两者含义不同，不相互替代。每轮结束保存物理占用，并在输出期间由后台任务每 200 毫秒采样一次，报告采样峰值与次数。采样峰值可能漏掉更短的瞬间峰值；哈希、采样和验证程序本身也会占用 CPU 与内存。

同一个真实视图连续承受三轮负载，可以观察历史容量达到上限后，轮末物理占用是否继续随总输入量增长。结束时关闭输入桥接和窗口、清除强引用，并检查终端视图的弱引用已经释放。三轮短测与视图释放检查不构成长时间内存泄漏证明，也不预设适用于所有 Mac 的内存预算。

空闲区间保留已经承受负载的终端视图，并启动正式拉取泵，让一次空通道读取挂起。此时停止输出期的延迟心跳与资源采样定时任务，10 秒后读取一次进程计数。断言该区间只有一次停驻读取、没有输出，也没有读取轮询。CPU 结果来自实际进程计数；仅仅等待 10 秒本身不作为“空闲 CPU 接近 0”的证据。

## 真实 SSH 渲染与交付证据

真实 SSH 的独立验证使用用户授权的 Linux VM、已批准的外部私钥和独立核对的主机指纹，通过正式 OpenSSH transport、PTY、签名 helper 和终端 `feed` 处理 16 MiB 相同 UTF-8 / ANSI 正文；远端仅在内存生成负载，不写远端文件。完整负载摘要在终端输入边界核对。本次使用从最终 ZIP 解压的应用中的 Hardened Runtime helper。

该夹具直接从正式 transport 的 PTY 通道读取，分隔负载标记后向真实 SwiftTerm 视图交付；**没有经过 `SSHSessionController` 或 `TerminalIOPump`**。它验证真实 SSH / helper / PTY 与终端解析路径，不能作为完整应用控制器链路的端到端速度。每约 1 MiB 请求一次隐藏窗口显示处理，这些 display pass 也不是物理显示帧率。该报告与本地三轮性能报告分开，不能把本地有界通道速度称为网络速度。

## 结果的适用范围

- 当前方法采用隐藏原生窗口与强制离屏绘制，不测可见显示器刷新率、合成器动画或交互输入到屏幕呈现的完整延迟。
- 本地负载不经过 SSH 网络；真实网络模式另外受虚拟机、网络、系统 SSH 和远端生成速度影响。
- 只有这台主机、本轮工具链、配置和短时负载得到测量；后台程序和系统调度会改变观察值。
- 每 200 毫秒的物理占用采样可能漏峰值；三轮轮末比较不能宣称长期无泄漏，RSS 与物理占用也不能简单相减解释为泄漏。
- 验证程序包含哈希、计数、资源采样与离屏位图开销；这些任务不会加入产品的空闲运行路径。
- macOS 14 实机、Intel / Rosetta、真实中文输入法候选、htop、实际睡眠唤醒和长时联网稳定性仍按验收矩阵逐项记录。
