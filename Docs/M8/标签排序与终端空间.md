# 标签排序与终端空间

日期：2026-10-29。版本：**0.1.0 / build 8**。

本轮按用户截图调整标签和远程终端空间：移除底部两栏，标签左侧单独编号、名称居中，并支持原生拖动排序。横排、竖排和标签视图沿用 [build 7 的方向规则](横排与竖排.md)。

当前状态：实现完成；独立可见窗口的双向鼠标拖动、原生事件链、三连接面板重排、Debug / Release 完整回归及资源搬迁均通过。build 8 的 arm64 本地预览已生成，ZIP 校验和解压审计通过。

## 范围与操作

### 终端空间

移除每个远程终端底部原有的“远程终端 / 列数 × 行数”栏，以及工作区最下方的连接状态栏。两栏原固定高度分别为 28 pt 和 31 pt，释放的空间交给终端；正常连接且没有额外提示时，远程终端正文延伸至工作区底部。

连接状态继续由标签状态点和右上角连接操作菜单显示。断开、重连和关闭操作仍在该菜单中。终端尺寸继续根据视图实际大小同步到各自远端 PTY，不依赖被删除的尺寸文字。

错误、主机指纹确认、密码输入与睡眠唤醒提示保留各自原有的处理方式。

### 标签外观与编号

- 每个标签最左侧单独显示编号，从 **1** 开始，按当前工作区顺序连续编号。
- 会话名称独立绘制，其中心对齐整个标签的中心；编号不拼接进名称，不以扣除左侧编号后的剩余区域作为居中基准。
- 状态点保留，× 位于右侧，选择与关闭使用独立点击区域。
- 新开连接追加至末尾；关闭一项或完成排序后，所有剩余标签立即重新编号。
- 横排和竖排中的面板标签显示同一工作区的全局编号；每个面板的编号不重新从 1 开始。

长名称按可用宽度截断。分屏很密集时，优先保留编号和 × 的操作空间；宽度不足 92 pt 的标签隐藏状态点，为文字和操作让出空间。极窄面板受实际屏幕宽度限制，不承诺完整名称或全部装饰同时可见。本轮不增加自动字号、滚动平铺或额外布局模式。

### 拖动排序

在普通标签栏按住标签的名称或编号区域，左右拖动到目标标签前后，看到插入指示线后松开。拖动过程中只显示落点，松开并确认落点有效后才提交新顺序。拖到标签栏边缘时可滚动访问溢出的标签；按 Esc 取消，或在无效位置松开，都不改变顺序。

横排或竖排时，同一工作区各面板的标签条也可以互相拖放。放到目标标签前半区插入其前，后半区插入其后；面板随新的标签顺序排列。横排保持一行 N 列，竖排保持 N 行一列，各面板继续均分对应方向的空间。

例如原顺序为 `1 A、2 B、3 C`，把 C 拖到 A 前，松开后变为 `1 C、2 A、3 B`。若当前输入目标为 A，排序后仍是 A；编号变化不改变连接身份。

排序只作用于当前窗口、同一工作区的现有连接。它保留选中的连接、认证请求、controller、终端视图、内容与滚屏历史，不新建连接、不重连，也不向其他终端发送输入。× 仍只关闭所属连接；关闭到一个终端时自动返回标签视图。

## 实现与 API

`TerminalTabsViewModel` 是顺序的唯一来源：

| API | 含义 |
|---|---|
| `reorderingID` | 当前工作区的临时排序作用域，供普通标签栏与面板标签条共享 |
| `ordinal(for:)` | 返回现有标签当前的 1-based 位置；未知或已关闭 UUID 返回 `nil` |
| `move(id:to:)` | 移动已有 UUID；目标为**移除原项后的最终 0-based 索引**，越界夹到首尾，未知 UUID 或原位移动不发布变更 |
| `tabs` / `allSessions` | 共享同一顺序；排序只重新排列已有对象，保留 `selectedID` 与布局模式 |

`TerminalTabBarItem.ordinal` 将当前编号传入原生标签单元。`TerminalTabBarRepresentable` 通过 `onMove` 返回移动操作，并通过 `reorderingID` 连接同一工作区的标签条。编号、名称、状态点和 × 分别布局；名称使用对称内边距实现整标签居中。辅助功能中的选择和关闭名称包含当前编号与会话名。

排序由 AppKit 标签按钮的 `mouseDown` → `mouseDragged` → `mouseUp` 事件链在当前窗口内处理，不启动系统 `NSDraggingSession`，不使用 pasteboard。跟踪只持有现有终端的 UUID；落点检查要求来源仍存活、UUID 仍属于来源标签栏、目的标签栏处于同一窗口且排序作用域匹配。分屏标签依靠全局编号计算目标位置。

指针位移达到 5 pt 后开始排序跟踪，避免拖动同时触发选择。松开时重新检查当前位置、来源 UUID 和最新编号，先清理跟踪状态，再最多调用一次 `onMove`。Esc 仅在当前窗口存在排序跟踪时被消费；窗口失焦、应用失去前台、关窗、源标签关闭、隐藏或视图拆除都会取消跟踪。

离开有效目的标签栏时，插入指示线隐藏、边缘滚动停止；在无效位置松开不提交。拖动停在有溢出内容的标签栏边缘时，使用间隔 60 ms 的可取消任务继续滚动。移离边缘、取消或结束排序后任务释放，空闲标签栏没有该任务。

`TerminalTabsPane` 将新的会话顺序交给现有持久终端宿主。宿主按 UUID 保留各终端及其固定父容器，只更新顺序和 frame；布局和尺寸变化继续使用既有 PTY 调整链路。`SSHSessionPane` 与 `WorkspaceView` 删除底部栏后，将可用高度交给现有终端视图。

隔离验证使用假会话及合成通道；测试窗口与用户正在运行的 DockShell 分开。原生按钮事件链回归与独立可见窗口中的实际鼠标拖动分别记录，代码检查不替代实际操作。

此前系统 `NSDraggingSession` 路径在独立控制窗口中收到了按钮鼠标事件，但未完成释放处理，该夹具未通过，不计作本轮通过证据。最终实现采用上述窗口内事件链；其双向真实鼠标操作及后续原生检查已完整通过。

验证器增加 `DOCKSHELL_REORDER_TEST=1` 的独立入口，需同时传入 `--ui-smoke`。可见拖动夹具另需 `DOCKSHELL_TAB_DRAG_MANUAL_TEST=1`，总等待期限为 300 秒。各独立测试模式应分进程运行。最终结果以相应过程退出 0 且出现 `PASS verification completed` 为准。

本轮回归及预览命令：

```sh
DOCKSHELL_UI_SMOKE=1 sh Scripts/test.sh
DOCKSHELL_UI_SMOKE=1 sh Scripts/test.sh release
sh Scripts/release.sh --local-preview
```

现有 183 个简体中文 / 英文资源键继续复用，本轮不新增本地化文案。

本轮使用当前 CLT 的 Swift 6.4 / macOS SDK 27。自动化构建环境设置 `DOCKSHELL_DISABLE_SPM_SANDBOX=1`，以运行已采用的 SwiftTerm 构建插件；普通终端继续使用脚本默认设置。原生构建方式的弃用提示不影响本轮退出码或完成标记。上游 SwiftTerm 与 ArgumentParser 的 checkout 均未修改。
