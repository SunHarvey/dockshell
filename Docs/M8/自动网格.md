最新 **build 7** 已按用户要求改为严格横排（1 行 N 列）或竖排（N 行 1 列），不再自动选择二维网格。当前行为见[横排与竖排](横排与竖排.md)，下文保留 build 6 的历史记录。

日期：2026-10-28。版本：**0.1.0 / build 6**。

用户已确认：无论打开多少个标签，分屏都只平均排列当前已打开的终端，统一采用自动网格，不创建标签或 SSH 连接。此交互替代 build 3–5 的双面板分屏组、左右 / 上下按钮及已保存会话选择器。

当前状态：**build 6 的 arm64 本地预览已完成**。最终 Debug、Release 的默认、原生 UI 及资源搬迁回归全部通过；181 个双语键、1000 个几何 frame、七连接模型、五终端网格和 120 点窄标签均有通过记录。独立可见测试窗口的真实 CUA 工具栏切换 ON → OFF → ON 已完成，五条原连接身份和连接调用次数不变。最终 ZIP 校验及带空格路径解压审计通过；新生产应用的实际使用由用户接续验证。

## 操作规则

- 一个现有标签始终对应一个原有连接身份。点击工具栏的网格按钮，平均显示全部已打开终端；再次点击恢复普通标签切换。
- 网格模式中，每个终端显示自己的名称、状态点和 ×；普通模式中，这些连接由顶部标签栏显示。两种标签区域互斥，不复制一组标签，也不建立新的分屏组。
- 点击网格面板或其标签，选择键盘输入目标。其他终端继续处理自己的输出及终端协议回复。
- 普通标签的 ×、网格标签的 × 和右上角“关闭终端”，都只关闭对应的一条连接。关闭后其余终端重新平均排列。
- 只剩一个终端时自动回到普通标签模式；零个或一个终端时网格按钮不可用。
- 双击侧栏会话或显式使用“在新标签中连接”仍会新开连接。若此时处于网格，新打开的终端加入现有网格；网格切换本身不会触发这个操作。
- 正在认证、已断线的终端保持各自状态。网格不取消凭据提示、不重新认证、不自动重连；现有手动重连入口继续可用。

布局切换保持同一终端、连接、历史和正在运行的程序。每个终端按自己的实际字符网格同步远端 PTY 尺寸；vim、htop 等程序收到尺寸变化后自行重新布局。

## 布局与所有权

`TerminalTabsViewModel` 不再拥有双面板组：每个 tab 只拥有一个 `TerminalTabSession`，模式是单独的 `isGridMode` 状态。切换模式不调用工厂或连接方法；选择和关闭继续使用原来的 session UUID。

每个终端从初次挂载起就位于同一个 AppKit 容器中。网格和标签模式只调整 frame、标签可见性及选中边框，不把运行中的终端换父容器，也不替换 SSH 内容的 `rootView`。未显示的普通标签仍保留视图、连接和有限的输出通道。

局部标签独立观察本连接的状态及认证提示，避免几何未变化时状态点不刷新。只有选中的连接允许自动恢复终端焦点；共享 field editor 的归属检查继续保护正在输入的凭据字段。这个焦点许可不限制后台终端的协议回复。

`TerminalGridLayout` 在 O(N) 时间内选择行数并生成 N 个 frame。行内等宽，各行高度补偿其面板宽度，使扣除间隙后的各终端面积相等。最后一行铺满，不留下未使用的网格单元。例如在 1280 × 720 的几何样例中，4 个终端为两行各 2 个，5 个为上 3 下 2，6 个为两行各 3 个；实际排列随可用窗口比例调整。

间隙会在极小区域中缩小，避免负尺寸；零或非法区域返回安全零尺寸 frame，保持 session 与 frame 的索引对应。未设置“两面板”数量上限。大量终端平均占用有限窗口时，单格尺寸和文字可读性会降低；可退出网格回到完整标签终端操作。本轮不引入自动改字号、网格滚动或布局保存。
