# M10.0：终端日志技术验证

更新日期：2026-10-31。本页保留 M10.0 独立命令行探针的历史结果；应用接入见 [M10.1 终端日志接入与验收](终端日志接入与验收.md)。M10.0 当时**尚未接入 DockShell 应用界面**。当前已安装的 v0.2.0 不会因运行探针自动获得日志功能。本轮不修改应用版本，不发布 Release。

## 已确认的产品规则

| 项目 | 规则 |
|---|---|
| 默认状态 | 默认开启，可在设置中关闭 |
| 容量 | 每个独立连接默认保留最多 **5 MB，即 5,000,000 字节**的文本，可通过设置调整 |
| 超限 | 滚动移除最早的内容，不无限保留旧分卷 |
| 多标签与分屏 | 每条连接分别计量，不因标签重排、分屏或同主机而合并日志 |
| 备用屏幕 | 略过画面内容，记录进入和退出时间；不根据命令名称判断 |
| 导出 | 终端内右键菜单提供“导出终端日志”，选择位置生成当前连接已保留日志的文本副本 |
| 关闭记录 | 之后的输出不写入日志；已经保留的内容仍可导出 |

用户最后一句中的“导入终端日志”结合“选择要导出的位置”，按**导出**理解。导出对象是该连接已经保留的会话日志，不是重新抓取当前滚屏历史，也不导出服务器上的文件。

容量是每个连接的上限，不是所有历史连接的总上限。尚未约定跨连接历史的保留期限或总容量，因此不擅自加入按天清理、全局删除规则。

## 验证入口

在项目根目录运行：

```sh
sh Scripts/test-terminal-logging.sh debug
sh Scripts/test-terminal-logging.sh release
```

成功时最后一行必须是：

```text
PASS M10.0 terminal logging probe completed
```

脚本构建 `M10/TerminalLogging` 独立 SPM 包，产物位于 `.build/m10-logging`。没有生成或启动 `DockShell.app`，不修改应用程序目录，不重新登记测试应用，不访问个人会话、Keychain、私钥或服务器。

文件探针使用当前用户临时目录下新建的 0700 目录，完成后清理。真实 PTY 探针只运行 macOS 自带的 `script`、`vim` 和一次性 `top -l 1 -n 1`；Vim 使用独立 HOME，禁止个人配置、插件、viminfo 和交换文件。开发诊断的英文提示不进入产品；M10.1 的菜单、状态、错误与日志标记必须使用 String Catalog。

当前 CLT 仍需 `--build-system native`，已知弃用提示保留，没有通过过滤 stderr 掩盖它，也不在本里程碑改动构建系统。

## 依赖与接入结论

| 依赖 | 版本 | SPM 来源 |
|---|---|---|
| SwiftTerm | 1.19.0，现有本地标识 `1.19.0+dockshell.1` | 上游 `https://github.com/migueldeicaza/SwiftTerm.git`，探针引用现有 `Vendor/SwiftTerm` |
| 其余 | Foundation、Darwin 与 macOS 自带命令 | 系统提供；没有新增第三方依赖 |

固定上游提交为 `464df5207fc2432e16c9a23abe538187196daf5f`。本轮没有修改 Vendor 文件、原有字体补丁或正式应用的依赖图。

当前 macOS `TerminalView` 的 `linefeed(source:)`、`scrolled(source:yDisp:)` 和 `bufferActivated(source:)` 是已有的 `open` 回调。探针编译了只调用 `super` 的子类以核对这些接口确实能从包外覆盖，没有编造额外观察者 API。

纯命令行测试用一个自己拥有的 `Terminal` 执行真实 SwiftTerm 解析。**应用接入时应观察原有视图的同一个解析器**，不再创建第二个终端解析器，也不替换其 delegate。原有回调行为必须继续调用 `super`。

仅在一整块输出解析结束后检查光标会漏掉“清屏/移动光标后又换行”的变化。`FeedBoundaries` 只划分输入边界，让控制序列完成时可以观察状态；全部字节仍由 SwiftTerm 解释，包含跨块 UTF-8、CSI 和控制字符串。它不是正则过滤器，也不是重新实现 VT 模拟器。是否改变实际 NSView 吞吐需在 M10.1 接入后测量。

## 文本提取规则与结果

| 验证场景 | 本机 Debug / Release |
|---|---|
| 中文、emoji、组合字符逐字节输入；过滤颜色序列 | 通过 |
| 退格纠错、CR 覆盖进度、未换行尾部 | 通过 |
| 长逻辑行跨多屏、自动折行及很小的解析器历史 | 通过 |
| 手动向上滚动后继续输出，仍取实时光标所在行 | 通过 |
| 备用屏幕 47 / 1047 / 1049，控制序列跨块 | 通过 |
| 同一数据块内普通未换行文本 → 备用屏幕 → 普通输出 | 通过 |
| 进入/退出时间事件；备用屏幕文字不进入文本事件 | 通过 |
| 普通清屏后继续输出 | 通过 |
| 未完成长行经过窗口尺寸重排，无旧文字重复 | 已有普通缩放夹具通过；任意复杂光标编辑不作完整保证 |
| 暂停期间输出不记录，恢复时不补回暂停前的半行 | 通过；半行略过有明确事件 |
| 超长未换行内容有界保留、截断元数据和导出提示 | 通过 |
| 真实隔离 PTY 的 vim 进入/退出与画面排除 | 通过 |
| 本机一次性 top 输出 | 通过；不误认为所有 top 都使用备用屏幕 |

提取依赖解析后的行，而不是原始按键。宽字符后占位单元不重复输出；只去掉空单元，不用字符串 `trim` 删除真实空格。普通日志不能还原所有任意光标重绘或文件编辑历史，不能当作 Vim 保存文件的副本。

恢复记录时，如果当前行包含关闭记录期间的文字，原型略过该半行至下一次硬换行，并生成说明事件。这避免恢复时把先前关闭记录期间的文字一并带入日志。此边界需在 M10.1 的中文提示中说明。

## 容量、文件与导出

原型使用独立连接目录内的小型 UTF-8 文本分段，默认每段最多 65,536 字节。达到总预算后删除最早的完整分段；不是“每段 5 MB 再无限新增文件”，也不每次重写整个 5 MB 文本。

- 稳定状态下保留的文本及导出中的截断说明不超过配置上限。
- 完整段淘汰会使实际保留量略少于上限；不保证恰好保留满 5 MB。
- 一次写入成功后再淘汰旧段，短暂磁盘占用可能多出一个分段；文件系统分配粒度与目录元数据也不计作有效文本。
- UTF-8 边界保持有效，但容量截断不承诺保留完整 emoji 字素组合或完整第一行；导出会明确说明较早内容已移除。
- 缩小容量立即淘汰旧段；扩大容量不恢复已移除内容。
- 一个连接的滚动清理不触及另一个连接。

文件读写通过有界后台 worker 执行，Actor 对外只暴露 async/await。文件状态仅归属于同一串行 worker，避免 Actor 在等待 IO 时重入而把快照和写入交错。不能为每个字符创建任务，也不能无限排队。生产接入仍需定义队列满、磁盘满和权限错误后的界面状态，并验证不静默继续声称完整记录。

导出在同一 IO 顺序中生成不可变快照，包含尚未换行的尾部；后续输出和滚动删除不改变已导出的文件。落盘使用同目录临时文件、同步文件及独占发布，权限 0600；原型遇到已有文件或符号链接直接失败，不覆盖、不留下半个导出文件。M10.1 接入 NSSavePanel 时，同名文件的实际交互还需验证。

实际界面中的导出请求还必须作为有序控制事件进入输出管道，将缓存内容和未换行尾部固定在同一截点；不能先读取 UI 尾部，再让后续输出插队写入。此交互顺序属于 M10.1 验收，独立文件快照通过不代表界面已经完成。

文件能力通过 `TranscriptStore` 协议隔离。已验证连接停止写入后仍可导出保留日志，关闭后的继续写入会明确失败。原型不会重新打开现有连接日志，因此重启后的历史读取和异常恢复不算已完成。

12,322,890 字节的合成文件写入与滚动夹具在本机 Debug / Release 均通过。输出的耗时包含操作系统缓存效应，**不是物理磁盘吞吐、掉电持久性、慢盘压力或界面帧率的验收结论**。正常停止及导出做文件同步，但不承诺进程崩溃或掉电零丢失。

## 下一里程碑：M10.1

下一轮才将能力接入真实 SSH 与本机 Shell：

1. 默认开启、设置关闭、每连接容量设置；保存后作用于当前及之后的连接，兼容已有字体/主题设置记录。
2. 在现有终端适配器中观察同一个解析器，保持网络输入、协议回复、IME、鼠标、复制粘贴及 `super` 行为。
3. 终端右键菜单“导出终端日志”与本机保存位置选择；简洁记录状态，不增加此前移除的底部栏。
4. 连接重连、标签关闭、应用退出的收尾，以及真实文件选择器和错误交互。
5. 高频输出、队列过载、写入失败、复杂重绘、缩放、多标签/分屏和后台记录验收。

应用认证框的密码、私钥口令和原始按键不接入日志。服务器输出或命令回显本身仍可能包含敏感内容，不能声称能自动识别并脱敏全部秘密。M10.1 必须提供明确记录状态和关闭入口。
