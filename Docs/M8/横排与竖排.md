# 已打开终端的横排与竖排

日期：2026-10-28。版本：**0.1.0 / build 7**。

2026-10-29 的 build 8 在保留本文件方向规则的基础上，加入左侧编号、居中名称和拖动排序，并移除底部两栏；最新交付与验证见 [标签排序与终端空间](标签排序与终端空间.md)。本文件保留 build 7 的历史验证记录。

按用户最新要求，布局菜单提供“横排”“竖排”“标签视图”。横排和竖排都排列全部已打开连接；布局操作不创建标签或 SSH 连接。此规则替代 build 6 的自动网格。

当前状态：横排、竖排和标签视图已实现；独立窗口的实际菜单操作、Debug / Release 完整回归及资源搬迁通过；arm64 本地预览包已生成，ZIP 校验和解压审计通过。

## 精确布局规则

| 已打开数量 | 横排：左右并列 | 竖排：上下堆叠 |
|---|---|---|
| 2 | 1 行 2 列，各占一半宽度 | 2 行 1 列，各占一半高度 |
| 3 | **1 行 3 列**，各占三分之一宽度 | **3 行 1 列**，各占三分之一高度 |
| N | 1 行 N 列，等宽、同高 | N 行 1 列，等高、同宽 |

所有面板使用同一方向，不会自动折成多行多列，也不让最后一个面板单独跨行。分隔间隙从可用尺寸中扣除，其余空间沿指定方向均分。

## 操作与连接身份

- 一个原有标签始终对应同一条连接。菜单选择横排或竖排时，全部现有终端按标签顺序显示。
- 每个面板保留自己的名称、状态点和 ×；点击面板或其标签选择输入目标。× 只关闭所属连接，剩余面板按当前方向重新均分。
- 选择“标签视图”恢复普通标签切换；标签和连接数量不变。普通标签栏与面板标签互斥显示，不复制一排标签。
- 关闭至一个终端时自动返回标签视图；零个或一个终端时不能启用多连接排列。
- 布局切换保留已有 controller、连接、终端视图、历史、认证请求和正在运行的程序。每个终端继续按自己的实际字符网格同步远端 PTY 尺寸。
- 双击侧栏会话或显式使用“在新标签中连接”仍可主动新开连接；这是独立的连接动作，布局切换本身不会调用它。

横排与竖排没有两面板数量上限。连接很多或窗口较小时，每个终端的可用宽度或高度会变小，标签与正文可读性受屏幕空间限制。可返回标签视图操作完整终端；本轮不添加自动改字号、滚动平铺或布局保存。

## 实现与验证范围

`TerminalArrangement` 明确表示 `.tabs`、`.horizontal`、`.vertical`。模式变更只调整现有终端的 frame 和标签可见性；终端保留固定父容器，SSH 内容宿主不换 `rootView`，焦点许可与后台协议回复仍分别处理。

部分内部文件名及测试宿主标识保留 `Grid` 字样以减少无关改动；这不代表继续使用自动网格算法。几何函数按照明确传入的横排或竖排方向生成 N 个 frame，不再选择或评分网格行数。

| 检查 | 当前证据 |
|---|---|
| 方向几何、三连接严格 3 列 / 3 行、均分与边界 | 通过；覆盖异常尺寸、间隙缩减及 1000 个 frame，严格保持单行或单列 |
| 现有连接数量、身份、认证和 IO 保留 | 通过；七连接模型反复切换，不新建、不重连，保留认证请求并隔离输入与输出 |
| 原生终端方向切换、各自 PTY、独立关闭和释放 | 通过；三个实际 SwiftTerm 视图及其父容器身份不变，历史保留，独立尺寸、焦点、后台协议回复、逐项关闭及释放通过 |
| 工具栏布局菜单的实际点击 | 独立可见窗口通过横排 → 竖排 → 标签视图 → 横排；同三条合成连接，factory 总调用 3 次、每条 connect 1 次，随后原生回归和最终完成标记通过 |

| arm64 本地预览、ZIP 校验和解压审计 | build 7 通过；应用与辅助程序的嵌套签名、Hardened Runtime、空 entitlements、架构、macOS 14 部署目标和内置资源均通过离线审计；ZIP 校验通过，解压到含空格路径后复审通过 |

隔离模型和 UI 夹具使用假会话及合成通道，不连接用户服务器、读取个人私钥或访问正式 Keychain。编译时的 macOS 14 部署目标不能替代该系统实机运行。真实中文 IME、真实密码保存后退出重启登录、实际睡眠唤醒、macOS 14 实机和 Developer ID / 公证等既有 M6 待验项继续保留。

菜单交互使用独立的 `DockShell Layout Verification` 窗口，不操作用户正在运行的 DockShell。手动夹具需要同时设置 `DOCKSHELL_SPLIT_TEST=1`、`DOCKSHELL_GRID_MANUAL_TEST=1` 并传入 `--ui-smoke`；当前总等待上限为 300 秒。前两次交互检查超出旧 120 秒等待上限，未计为通过；最终检查完成全序列并以退出码 0 结束。

本轮完整回归命令：

```sh
DOCKSHELL_UI_SMOKE=1 sh Scripts/test.sh
DOCKSHELL_UI_SMOKE=1 sh Scripts/test.sh release
sh Scripts/release.sh --local-preview
```

执行环境为当前 Apple Silicon、Swift 6.4 / macOS SDK 27；自动化执行环境另设置 `DOCKSHELL_DISABLE_SPM_SANDBOX=1` 以允许 CLT 的构建插件运行。仍使用现有原版 SwiftTerm 的构建方式；工具输出的旧构建选项弃用提示不影响本轮退出码和验收结果。SwiftTerm 与 ArgumentParser 的上游 checkout 均无修改。
