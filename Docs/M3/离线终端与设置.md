# M3：离线终端与设置

> 本文保留 M3 历史实现与验证记录。当前已推进 [M4 密码 SSH 与主机信任](../M4/密码SSH与主机信任.md)，真实连接期间的字体应用策略已在 M4 确认并实现。

日期：2026-10-28。继续在当前 `DeckShell` 目录开发，产品名 DockShell。本轮只实现 M3，不连接服务器，不启动本地 shell，也不读取会话凭据。

## 已实现

- SwiftTerm 的 AppKit 视图，通过 `NSViewRepresentable` 接入 SwiftUI。
- 主窗口“打开离线终端”，提供 256 色、TrueColor、中文文件名、中文输出、emoji、组合字符样例。
- 原生键盘、鼠标、选择、复制/粘贴及 NSTextInputClient 输入路径；保持 IME 标记与提交过程。
- 本机输入回显。它不是命令解释器，不执行输入的命令。
- 本机生成 20000 行 UTF-8 的大输出检查。
- 字体、字号、石墨/深海/纸白三套原创主题，以及可调整的滚屏历史。
- 默认 Menlo / 14 / 石墨 / 10000 行。字号 8–40，历史 1000–100000 行。
- 版本化 UserDefaults 设置存储，损坏或高版本记录明确报错并保留。
- 关闭、取消、越界拖选及任务生命周期清理。

会话、分组、SQLite 与 Keychain 保留 M2 行为。SSH 密码登录、主机信任、PTY 进程与断线检测留在 M4/M5。

## 运行

先用 ⌘Q 退出已打开的旧版 DockShell，在当前目录执行：

```sh
sh Scripts/run.sh zh-Hans
```

打开“离线终端”，可直接输入文本，也可点击“重载样例”或“测试大输出”。打开工具栏设置按钮，或使用应用菜单“设置…”/⌘,，修改偏好后保存。

默认自动检查不需要图形交互：

```sh
sh Scripts/test.sh
```

具有桌面会话时，加入实际 AppKit 适配器、IME、鼠标和释放检查：

```sh
DOCKSHELL_UI_SMOKE=1 sh Scripts/test.sh
```

Release：

```sh
DOCKSHELL_UI_SMOKE=1 sh Scripts/test.sh release
```

所有自动数据流与会话检查使用隔离数据；设置检查使用随机 suite。适配器检查使用自己的隐藏窗口，不读取剪贴板、不切换系统输入法。真实中文输入法的候选选择、连续组合与候选窗口定位仍需用户人工验收。

## 数据流与并发

```text
本机生成器 Actor
    │ write，缓冲满时挂起
    ▼
BoundedTerminalChannel Actor（固定 64 KiB 环形缓冲）
    │ read（最多 4 KiB）
    ▼
TerminalIOPump Actor
    │ 等待 MainActor 完成这一块，再读取下一块
    ▼
TerminalSurface protocol → SwiftTerm AppKit 适配器
```

原始字节不先转换为分块字符串；UTF-8 解码状态由终端解析器保留。终端输入与解析都在 MainActor，遵守上游对同线程调用的要求。输出分块不会逐包发布 SwiftUI 状态，空闲读等待 continuation，不运行轮询循环。

“不丢数据”指所有收到的字节按序进入解析器。历史行有明确上限，旧滚屏会被移除，不等同于永久日志。M3 没有写终端日志。

输入保持事件顺序。样例生成期间先排队，等样例写完后再回显，避免两路数据在 UTF-8 标量中间交错。离线输入队列上限 1 MiB，超限整次输入明确拒绝，不部分注入；可等待后分段重试。CR 在本地回显时转成 CRLF，未来 SSH 输入不会沿用这个演示转换。

## 原生终端边界

`SwiftTerm` 具体类型只在 `DockShellTerminalUI` 及独立诊断模块出现。Features、业务与基础设施通过领域设置、`TerminalSurface`、连接通道协议和控制器边界协调。

适配器保留原生文本输入客户端，不重写键盘事件来替代 IME。复制、粘贴、全选菜单标题从 String Catalog 注入。字体仅在名称或字号真正变化时更新；主题更新不重置解析器。设置窗口按字体元数据枚举等宽字体，不实例化全部已安装字体。

视图挂载先登记弱引用，再延后启动与发布状态；早期输入仍按序排队。尺寸回调合并后再发布，关闭立即取消 IO，旧视图回调按来源身份过滤，避免替换后污染新终端。真实 NSHostingView 检查覆盖创建、字体更新、替换和拆除期间不发生同步状态发布。

原版 1.19.0 的选择拖动自动滚动计时器没有公开 shutdown 接口。适配器在卸载时关闭报告与链接副作用，调用公开 mouse-up 清理路径停止拖动，再移除 delegate、菜单和活动任务。弱引用释放检查覆盖越界拖选情形。

终端 DEBUG 解析日志关闭，避免终端内容进入调试输出。默认采用 CoreGraphics 与稳定光标；本轮不启用 Metal 渲染。

## 依赖与 CLT 构建

| 依赖 | 固定版本 / 提交 | SPM 地址 |
|---|---|---|
| SwiftTerm | 1.19.0 / `464df5207fc2432e16c9a23abe538187196daf5f` | `https://github.com/migueldeicaza/SwiftTerm.git` |
| ArgumentParser（上游解析依赖） | 1.8.2 / `6a52f3251125d74daf04fcbd5e6f08a75d074382` | `https://github.com/apple/swift-argument-parser` |

版本由根 `Package.resolved` 锁定。应用只链接 SwiftTerm 库，ArgumentParser 用于上游的其他产品，不链接进本应用。上游声明的 swift-docc-plugin 未进入本次实际解析图。没有 fork、补丁或修改第三方 manifest。

CLT 的默认 swiftbuild 会尝试离线编译上游 Metal 资源，而当前机器没有 `metal`。本轮在公共构建函数中**显式采用 `--build-system native`**，同时保持最低部署目标 macOS 14。该构建方式已弃用，将来可能移除；工具链升级时必须重新验证，不能视为长期无维护保证。

SwiftTerm 的 BuildInfo 插件会执行：只读取依赖 checkout 的 Git 元数据、执行本地 Git 查询，并在自己的 plugin-work 目录生成信息文件；不访问网络、凭据或改写项目源文件。普通终端保留 SPM sandbox；Codex 嵌套受限环境可按 README 显式设置禁用开关。本次没有运行其文档 command plugin。

打包脚本动态读取 `--show-bin-path`，原样复制 `SwiftTerm_SwiftTerm.bundle` 到 `Contents/Resources`。该资源包只有 Shaders.metal，没有 Info.plist；上游实际资源查找支持这个标准位置。没有修改生成的 Bundle.module，也没有依赖源码目录兜底。

SwiftTerm 的完整版权许可随应用的 `Contents/Resources/ThirdPartyNotices.txt` 分发。

## 本轮实测记录

宿主 macOS 27.0.1 / arm64，Apple Swift 6.4、SDK 27.0。最终 Debug 与 Release 构建、通道/完整链路检查、终端适配器及真实 SwiftUI 生命周期检查均退出 0；双语资源为 122 个类型化键。原版依赖 checkout 保持干净。真实系统中文输入法候选交互与 macOS 14 运行仍待人工验收。

桌面实际检查已看到完整颜色与中文/emoji 样例、中文粘贴回显、20000 行末尾输出，以及纸白主题保存后即时应用。设置测试后恢复为原先的 Menlo / 14 / 石墨 / 10000 行。

以下为同一优化后 Debug 进程的短时采样，终端为 95 × 32，历史上限 10000 行：

| 场景 | 空闲 CPU | RSS |
|---|---|---|
| 新进程主窗口 | 0.0% | 约 116 MiB |
| 打开终端、字体设置后，第一次 20000 行样例完成 | 0.0% | 约 204 MiB |
| 同进程再运行一次 20000 行样例并空闲 | 0.0% | 约 206 MiB |

这不是内存上限或长时无泄漏证明，也不是最终 Release 预算。当前已经避免全量字体实例化、按包刷新 SwiftUI 和无界输出队列；服务器负载、长时内存与不同历史/窗口组合继续在 M6 评估。

## 已知限制与后续验收

原版 SwiftTerm 1.19.0 在修改字体时会 soft-reset 部分终端协议模式，内容历史保留。M3 离线字体调整已验证；**M4 接入真实 SSH 时必须决定并验证字体应用时机**，不能将本阶段结果等同于运行中的 vim 模式完全保留。当前没有为此修改上游。

实际 macOS 14、真实中文输入法候选交互、vim/top/htop、网络全链路背压、keepalive、睡眠唤醒、长时内存与空闲 CPU 验收仍保留在相应阶段。部署标记和本机检查不能替代目标系统实测。
