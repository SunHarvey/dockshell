# M7：多标签实现与验收说明

日期：2026-10-28。用户已选择 M7 多标签。本轮实现同一主窗口的多个独立 SSH 终端标签，保持现有 Swift 6、macOS 14 最低部署目标和 CLT 构建方式。应用版本为 **0.1.0 / build 2**。

当前已通过 Debug / Release 完整回归、资源搬迁及多标签原生界面检查，包含后台光标查询回复和八标签溢出用例；并在已授权的 Linux VM 中实测两个独立连接。0.1.0 / build 2 的 arm64 Hardened Runtime 本地预览包已生成，ZIP 校验、含空格路径解压审计、资源封印和防误上传检查均通过；解压包也已通过真实双标签连接与切换检查。

## 1. 已实现的使用方式

- 在侧栏选择一个已有会话后，点击工具栏“在新标签中连接”或按 **⌘T** 打开独立终端。
- 双击侧栏会话，或通过该会话的右键菜单打开新标签。
- 同一个会话配置可以重复打开；每次有独立运行 ID、SSH 连接、终端内容和状态。
- 点击原生标签条切换终端。后台连接继续接收并解析数据，切回时保留原画面、历史和终端模式。
- 每个标签显示自己的连接状态；等待主机确认或凭据的标签有提示，选择后处理对应决定。
- 关闭一个标签仅关闭它的连接。关闭后台标签保留当前选择；关闭当前标签后选择相邻标签。关闭全部标签后回到会话工作区。
- 离线终端入口保留，只有没有 SSH 标签时可用。切换到离线终端不会中断已有 SSH 标签。
- 设置仍全局共享。主题和历史上限更新各终端；连接中的标签继续冻结字体和字号，到下次连接再生效。

标签条和原生容器使用 AppKit，经 `NSViewRepresentable` 嵌入 SwiftUI。新增文案在 String Catalog 中提供简体中文和英文。拖动排序、工作区自动恢复、多窗口、分屏、SFTP 和其他第二阶段功能没有纳入本里程碑。

## 2. 模块与资源所有权

| 类型 / 位置 | 实际职责 |
|---|---|
| `TerminalTabsViewModel`，Features | 管理标签集合、选中运行 ID、打开 / 选择 / 关闭，以及每个子状态的观察转发 |
| `TerminalTabSession`，Features | 独立运行身份，拥有一个 `SSHSessionController` 和一个 `SSHConnectionPrompts` |
| `TerminalSessionFactory`，Features 协议 | 将运行实例的创建留给应用组装层；Features 不导入具体 SSH 实现 |
| `OpenSSHTerminalSessionFactory`，AppContainer | 每个标签创建新的 prompts、transport、controller 和独立睡眠事件流 |
| `TerminalTabBarRepresentable`，TerminalUI | 原生标签状态、选择 / 关闭按钮、横向溢出及无障碍动作 |
| `TerminalTabsPane` / `PersistentTerminalTabsView`，Features | 按运行 ID 持有每个标签的 `NSHostingView<SSHSessionPane>`，保持挂载、切换可见性并恢复焦点 |
| `SSHSessionController`，TerminalUI | 沿用每连接 generation、拉取泵、输入队列、尺寸同步和异步关闭链 |

应用级共享同一个凭据仓库 Actor、known_hosts Actor 和设置服务；每个标签的提示、transport、controller、连接、PTY、凭据 broker 和通道相互独立。运行 ID 与配置 ID 分离，同一配置打开两次不会共用终端或控制器。

侧栏选中的配置和当前选中的终端标签分别保存。运行标签使用打开时的配置快照；标签切换不重新认证，也不重新读取配置后替换现有连接。真实睡眠事件通过各控制器自己的观察流传递，不把一个单消费流当成广播。

## 3. 保留后台终端与正确路由输入

### 持久视图

每个标签的 `NSHostingView<SSHSessionPane>` 只创建一次，关闭该标签前一直保留在原生容器中。切换只设置可见性，不重设 `rootView`，不拆卸终端 representable。后台数据继续经原有有界通道和每次至多 4 KiB 的拉取泵进入所属 SwiftTerm。

原生容器为隐藏和可见子视图保持同一合法布局尺寸，只有 frame 实际变化才赋值，避免状态更新造成重复 SIGWINCH。隐藏标签没有改成 0 × 0，也没有额外积累未解析输出的无界数组。

集成时曾发现第二标签一直停留在 connecting。诊断确认原生宿主 representable 仅携带稳定的模型引用，SwiftUI 跳过 `updateNSView`，导致第二个终端没有挂载。现显式传入 `tabs` 和 `selectedID` 值快照驱动结构变化，保留已有视图身份；没有通过重建整个工作区或延长超时绕过。

### 焦点与认证提示

选择标签时先通过正常 AppKit responder 过程释放旧焦点，再隐藏 / 显示对应视图，布局完成后恢复选中终端焦点。有主机或密码提示时不会强制把焦点移回终端。后台状态变化和新后台视图不会抢焦点；底层终端的 `focus()` 也检查自身是否位于隐藏祖先中。

每个标签持有自己的 prompts。主机确认、密码、私钥口令以及取消操作都交给所属实例和 request UUID；关闭一个标签只取消它的 continuation。模型会拒绝错误工厂复用控制器、提示或运行 ID，防止两个标签意外共用状态。

SwiftTerm delegate 的 `send` 同时用于用户输入和终端协议回复。后台终端仍需回答服务器的光标状态查询，因此没有粗暴屏蔽所有后台 `send`。新增 DSR 用例验证隐藏 A 的回复回到 A，同时 B 不收到该回复；它与用户输入隔离分别断言。该新增用例的实际执行状态见第 5 节。

多标签切换时真实中文输入法的候选位置、连续组合与提交归属仍需人工验收；合成 `NSTextInputClient` 提交不能替代真实 IME 检查。

### 关闭与释放

关闭标签时取消该实例的提示和 IO，移除其宿主。原有关闭链和析构任务继续拥有连接资源，直到完成关闭回收，不阻塞主线程。验证器实际等待通道和连接关闭，并检查控制器与终端视图的弱引用释放；不会仅凭标签从列表消失就认定回收成功。

## 4. 构建与复现

仍使用当前 Command Line Tools，不需要安装完整 Xcode 或登录 Apple 账号。先退出旧 DockShell，进入当前工程目录：

```sh
cd "/Users/harvey/Documents/github-code/DeckShell"
sh Scripts/run.sh zh-Hans
```

基础完整回归和资源搬迁：

```sh
sh Scripts/test.sh
```

包含原生终端与工作区界面的完整检查：

```sh
DOCKSHELL_UI_SMOKE=1 sh Scripts/test.sh
```

已构建后，可单独运行 M7 模型、标签条和持久宿主检查，避免每次重复其他阶段的完整回归：

```sh
export DOCKSHELL_ROOT="$PWD"
. Scripts/common.sh
bin_path=$(swift_build -c debug --show-bin-path)
DOCKSHELL_TABS_TEST=1 "$bin_path/dockshell-verify" "$PWD/Build/debug/DockShell.app" --ui-smoke
```

`DOCKSHELL_TABS_TEST=1` 只选择 M7 验证模式；`--ui-smoke` 才额外创建原生标签条和终端工作区。它使用临时仓库和合成通道，不连接真实服务器、读取个人私钥或访问正式 Keychain 项。该可选模式不能与性能、真实网络渲染或 Keychain 重启模式同时开启。

Release 对应命令：

```sh
sh Scripts/build.sh release
DOCKSHELL_UI_SMOKE=1 sh Scripts/test.sh release
```

工具环境如限制嵌套 SwiftPM 构建子进程，可沿用已记录的 `DOCKSHELL_DISABLE_SPM_SANDBOX=1`，不修改系统策略或原版第三方源码。首次构建仍需固定提交已在缓存中或能够从官方 SPM 地址获取。

### 最终包的尺寸同步和双连接空闲采样

最终包在真实连接下调整窗口后，分别核对了当前标签 UI 行列与远端 `stty size`。UI 使用“列 × 行”，`stty` 返回“行 列”：

| 标签 | UI 显示 | 远端 `stty size` | 结果 |
|---|---|---|---|
| A | 132 × 29 | `29 132` | 对应一致 |
| B | 125 × 29 | `29 125` | 对应一致 |

这说明每条连接都同步了自身终端的实际 grid。两个标签列数不同的有限观察及尚未定位的原因，在下一节保留，不将它解释为远端收到错误尺寸。

已对最终预览应用和两条处于空闲 shell 的系统 SSH 子进程进行 **15.0171 秒**只读采样，期间没有 UI 输入。原始数据为 [application-idle-two-tabs.json](../../Build/Reports/M7/application-idle-two-tabs.json)：

| 进程 | 累积 CPU 时间差 | RSS 开始 → 结束 |
|---|---|---|
| DockShell 应用 | 0.00 秒 | 165511168 → 165511168 字节 |
| 系统 SSH 1 | 0.00 秒 | 3506176 → 3506176 字节 |
| 系统 SSH 2 | 0.00 秒 | 3538944 → 3538944 字节 |

CPU 来源是 `ps` 累积计数的差值，精度为百分之一秒；0.00 秒表示本次增量低于计数分辨率，**不能称为绝对零 CPU**。RSS 与物理占用不同，各进程可能共享页面，不能把这些 RSS 简单相加当成唯一物理内存。这是本机短时双连接空闲观察，不是长期稳定性、峰值内存或吞吐 benchmark。

- macOS 14 实机 / 虚拟机运行；最低部署标记和当前新系统编译不能替代它。

- 最终包真实中文 IME，以及多标签切换时的候选、组合、取消与提交。
- 真实 VM 密码保存到 Keychain、应用完全退出后重启回读并登录；既有合成新进程检查不替代该实际操作。
- Developer ID 正式签名、公证和官网发布；当前仍无对应证书，未上传 Apple 或发布网站。

详情见 [M6 验收矩阵](../M6/验收矩阵.md)。M6 的性能数值属于当时单终端测量，不能直接当作 M7 多标签吞吐、总内存或长期稳定性的结果。隐藏标签保留各自有限历史，整体内存仍随打开终端数量增加。

另有一个有限的显示观察需要复查：在同一窗口先后选择 A、B，分别看到 132 和 125 列，行数同为 29，各自与远端 PTY 一致。源码审查未见宿主裁剪，但本轮没有采集两个视图当时的实际字体和创建时显示缩放，尚未定位两者不同的根因。初始像素换算或字体快照是可能方向，仅属推断，需在不同显示器及受控字体条件下继续取证。没有因此修改上游，或在连接期间强制重新设置字体；也没有将此观察误记为断线或 PTY 尺寸同步失败。
